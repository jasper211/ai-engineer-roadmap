# IA与公众号输入覆盖评估 v0.1

## 1. 回答

IA网站资源可以被系统化、较完整地用作HKIA的**监管事实主干**，但不能单独构成完整行业分析。

“完整使用”不等于把所有文件一次性下载，而是做到：

```text
栏目完整发现
→ 附件和历史期登记
→ Theme与证据权限路由
→ 按Contract取用
→ 原始Asset与单元格/页码溯源
→ 定期监测更新和修订
```

## 2. IA能够提供什么

| 信息域 | 主要支持 | 当前观察 |
|---|---|---|
| 年度/季度长期业务 | T00/T01/T02/T10-T13/T20 | 监管事实主干，表式断点需治理 |
| 保险公司与财务资料 | T20/T32 | 可补主体、财务与资本观察，但需逐项核验粒度 |
| 中介牌照 | T22/T30 | 当前持牌规模与业务资格，不等于活跃度或产能 |
| 经纪/代理调查 | T12/T22 | 有专项报告，但较旧或单次，不能代表当前全市场 |
| 投诉统计 | T02/T12/T22/T30 | 已发现2017—2025附件；件数不等于行业发生率 |
| 监管文件与新闻稿 | T14/T30及受影响Theme | 提供政策事件和部分MCV摘要，不能自动证明因果 |

## 3. IA无法独立证明什么

- 客户为什么选择某产品、币种或渠道；
- 渠道的真实经营打法和组织能力；
- 活跃代理人数、生产率和留存；
- 公司内部执行动作；
- 利润、EV和资本回报的完整机制；
- “监管/宏观因素导致市场变化”的因果关系。

因此完整分析还需要公司一手披露、行业媒体/专家、内部经验、客户/销售研究和宏观数据。

## 4. 公众号试点结果

公众号可用于补充：

- 行业正在讨论什么；
- 市场参与者如何解释现象；
- 潜在机制、案例、术语和待查来源；
- 公司/渠道的公开叙事。

但本次真实试点显示：搜索索引可以取得标题、公众号、日期和摘要，微信原文在当前环境中不能直接进入。因此只能完成Source Lead登记，不能完成全文证据抽取。

样本“香港保险投保三大渠道怎么选?90%高净值客户都选IFA”含明确商业推广倾向，而且标题比例没有样本、分母和方法。正确处理是：

```text
“90%”不进入Fact
→ 登记为Media Claim候选
→ 识别发布者利益冲突
→ 转换为客户渠道选择研究问题
→ 要求独立客户/销售证据
```

这证明公众号输入会提高**问题发现和机制覆盖**，但只有经过回溯和交叉验证后才能提高结论等级。

## 5. 下一阶段输入组合

建议采用三层输入，而不是单源替代：

1. IA：事实底座和监管边界；
2. 公众号/LinkedIn/行业网站：观点、机制假说和来源线索；
3. 老板经验：优先级、适用情境、反例和决策映射。

三者进入不同对象，最终在Claim层汇合，不能在原始输入层混写。
