# 港险宝宝PRO语料试点与规模化路线 v0.1

## 1. 为什么适合作为测试对象

搜狗微信索引显示约486篇相关文章，发布者多次显示为“港险宝宝PRO”，当前检索到的时间覆盖2017—2026。普通搜索结果不按时间排序；加入近年限定后，当前最新索引候选为2026年8月3日的《国务院第841号令〈出境入境管理规定〉全文解读！对香港保险有什么影响？》。搜索索引可能有收录延迟，仍需与用户手机端公众号主页核对。文章同时包含产品营销、理赔案例、资产配置、宏观叙事、税务/监管主张、客户教育和品牌内容。

这类语料的价值不是充当事实数据库，而是验证：

- 行业叙事如何随时间变化；
- 哪些客户问题和产品卖点被反复强调；
- 渠道如何解释客户需求；
- 哪些数字、案例和监管说法需要回溯；
- 商业推广内容如何被证据Gate限制。

## 2. 不直接处理486篇

第一轮使用12篇分层样本：

| 样本组 | 数量 | 验证目标 |
|---|---:|---|
| 监管/税务/法律主张 | 3 | 高风险主张识别与官方回溯 |
| 产品/资产配置 | 3 | Fact、营销表述和机制假说拆分 |
| 理赔/客户案例 | 3 | 单例边界、隐私和代表性控制 |
| 渠道/客户教育/品牌 | 3 | 渠道叙事、客群假说和无分析价值内容过滤 |

12篇先由人工完成金标准，再让DeepSeek输出相同Schema。只有Fact/Opinion分类、引用定位和过度推断控制达到要求，才进入50篇扩展测试，最后处理完整语料。

## 3. 分阶段路线

```text
Stage 0 账号身份确认与原文取得方式
→ Stage 1 12篇人工金标准
→ Stage 2 DeepSeek盲测与误差复盘
→ Stage 3 50篇批量_主题聚类_重复来源检查
→ Stage 4 约486篇历史语料处理
→ Stage 5 增量监测新文章
```

## 4. DeepSeek在系统中的位置

DeepSeek只处理已经取得并允许外部处理的原文：

```text
原文Asset
→ DeepSeek结构化抽取
→ 确定性引用校验
→ Evidence Steward回溯事实
→ Challenger识别偏差与反例
→ 人工Gate
→ Claim候选
```

不能让DeepSeek直接抓微信、补写文章缺失内容、把公众号主张改写成事实，或把单个理赔案例推广到全行业。

## 5. 当前需要的最小输入

为了开始Stage 0/1，需要：

1. 公众号主页截图或微信号，用于确认账号主体；
2. 首批12篇不必一次提供，可先提供3篇完整原文；
3. 每篇可接受链接、PDF/HTML导出、完整截图或全文复制；
4. 确认这些文章是否允许发送至DeepSeek API处理。

API Key不写入项目文件，待真正接入时使用环境变量或Secret Store。
