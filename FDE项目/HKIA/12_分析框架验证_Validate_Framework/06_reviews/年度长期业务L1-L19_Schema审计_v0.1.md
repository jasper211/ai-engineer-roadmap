# 年度长期业务L1—L19 Schema审计 v0.1

## 结构结论

L1—L19不能使用一个“万能宽表”直接拼接。它们应拆成四个事实族：市场金额/数量、市场终止率、公司有效业务、公司新造业务。

| 事实族 | 表 | 主要粒度 |
|---|---|---|
| 市场趋势与专题 | L1—L4、L6—L7 | 年份×业务范围×保险种类×指标×维度 |
| 自愿终止率 | L5 | 年份×相连属性×保单年度×分红属性×险种 |
| 公司有效业务 | L8—L13 | 2024×保险公司×业务范围×指标 |
| 公司新造业务 | L14—L19 | 2024×保险公司×业务范围×缴费方式×指标 |

## 连接关系

- L2和L3是L1有效个人人寿业务的细分验证表。
- L14和L15应与L16按公司和指标对账。
- L8—L12与L13、L16—L18与L19只先建立对账关系，不预设简单加总恒等式。
- 所有公司表必须先通过保险公司名单建立稳定`insurer_id`，不能只用中文或英文简称跨年连接。

## 关键红线

1. 市场总额与公司明细不能同时计入聚合。
2. 保单数、受保人数和计划数不能合并成同一数量指标。
3. 市场表使用百万元，公司表使用千元，统一前必须转换单位。
4. L5是百分比事实，不能进入金额事实表。
5. `Current Estimate`不能改名为EV、VONB、利润或偿付能力资本。
6. `N.A.`、空白、零和未披露必须保留为不同状态。

## 下一步

第一条可复算链L14+L15=L16已经通过。第二条L8—L12到L13也已完成：57家公司在保额、整付、年付和Current Estimate上全部归零；L13来源标注的“保单数”实际还包含L11退休计划数，因此统一字段改为`policy_or_scheme_count_source_total`，而L11明细仍保留`scheme_count`，不得伪装成保单数。

第三条L16、L17、L18到L19的对账已完成。正确关系为`L16 + L17 + L18 = L19`；57家公司、4项指标全部归零。若只用L16+L18，会产生56项差异，且差异正好等于L17，证明个人年金不包含在L16个人人寿总额中。

三条公司级控制链现已通过。L1—L3市场历史链也完成了第一次验证，但结论不是一个可无条件推广的等式：

- 2020—2024保单数均满足`L2非相连 + L3相连 = L1总额`，5个年度无差异。
- 保费的最大差异为0.1百万元，来自历史展示值按0.1百万元舍入；2024未舍入值精确归零。
- 净负债/Current Estimate只有2024直接归零；2020—2023的L1还包含两条无文字标签的调整行，直接使用L2+L3会分别差31,796.0、37,042.3、14,378.9和104,538.1百万元。Agent必须按年份和行结构判断，不能把2024公式反推至历史。
- L3没有发布保额表；L1中2020—2023相连保额明确为`N.A.`，2024才给出546,178.604百万元。历史L1总保额与L2近似相等不能解释为相连保额为零。
- L2的2023年份表头显示`#NAME?`外部公式错误，只能以列序、相邻年份及公式审计恢复，不能回写官方源文件。

这次验证把市场表规则从“表之间可连接”推进成“每个指标、每个时期分别定义连接关系”。

L4与L14—L16的2024跨粒度控制也已完成：57家公司明细在L14、L15、L16中分别与来源市场总额完全一致；公司表从千元转换为百万元后，L4非相连业务与L14总额、L4相连业务与L15、L4全部个人人寿与L16总额均归零。2024新造个人人寿市场总额为986,208份保单、206,887.727百万元保费。

该验证不能被解释为所有维度均可互换。L4非相连业务按“分红/其他业务”拆分，L14按“整付/年付”拆分，两者只能在共同粒度——总保单数、总保费——对账；L4相连业务与L15才可按整付/定期缴付逐项核对。

L6与L10、L11、L18也已完成2024控制：三张公司表的57家公司明细均与各自市场总额一致，转换千元与百万元后，L6a非退休团体有效业务、L6b退休计划有效业务及L6c非退休团体新造业务的全部可比指标均归零。关键语义边界是：L6b在2024年保单数和受保人数均为`N.A.`，但计划数为365,637；这三个指标必须独立保存，不能用计划数填补另外两个字段，也不能把`N.A.`写成零。

年度控制链的主要数量和金额关系至此已覆盖个人人寿、团体及退休计划。

L7年金业务与L12、L17的控制也已完成。L12和L17的57家公司明细分别与各自市场总额一致；单位转换后，L7a的2024总保单数、总保费、Current Estimate与L12归零，L7b新造个人年金则可按整付/定期缴付四项指标与L17逐项归零。

L7a的等式具有严格年度边界。L7a标题包含个人年金、团体年金、永久健康、联合养老保险及资本赎回等业务；2022—2023仍有相连年金和其他业务数值，而2024这些类别均为`N.A.`，因此2024总额才恰好等于非相连个人年金并与L12一致。Agent不得把`L7a=L12`推广成历史恒等式。另一方面，L7b的2024相连新造年金是明确的零而不是`N.A.`，零和不适用必须继续分开。

至此L1—L7市场业务族与L8—L19公司业务族的主要控制链已闭环。下一阶段不应继续只做单表对账，而应进入“跨年份复验”：选择2023或2025年度包复跑规则，区分稳定规则、制度切换规则和2024特例。

## 2023跨年份复验首轮

2023年度完整包共22份Excel已从IA年度统计页面落库并完成文件签名与SHA256校验。公司表市场总额位于第70行，动态识别出59个公司实体，不沿用2024年的57家公司硬编码。

首轮复跑得到两项关键结果：

- `L14 + L15 = L16`在2023年59家公司、4项指标共236个单元格全部归零；加上2024年的228个单元格，该关系已经连续两个年度通过，但按三期晋升规则仍处于`validated_2_of_3`，尚未成为无条件稳定规则。
- 2023年`L17 + L18 = L19`也在236个单元格全部归零，但这不是2024公式的再次验证。2023年的L17、L18、L19分别代表非相连个人年金、相连个人年金和个人年金总额；2024则分别代表个人年金、非退休团体和全部长期新造业务总额。

这证明表号不是跨年稳定业务主键。Agent必须先读取报告年度和表标题，选择Schema版本后才能映射业务含义；否则同一个`L18`会把“相连年金”与“团体业务”错误串联。下一步继续复跑2023的L8—L13有效业务控制，并核对旧制度下L10—L12的业务含义和列序变化。

2023的L8—L13有效业务控制也已完成：59家公司、5项指标公式共295个单元格全部归零，市场总额同步归零。公式图仍为L8—L12分指标汇入L13，但组件的业务语义发生变化：2023年L11使用保单数与受保人数，2024年改为计划数；2023年L12包含年金及其他业务，2024收窄为年金；L10也从团体人寿变为非退休计划团体业务。

此外，2023公司表把年付放在整付之前，2024则把整付放在年付之前。若Agent依赖固定列号而不是双语表头，金额不会报错却会被静默调换。由此形成第二条跨年核心规则：**表间加总图可以稳定，但每个节点的业务范围、数量类型和列位置必须由年度Schema解释。**

下一步进入2023市场表L1—L7复验，重点检查历史列、L7其他业务以及L6团体/退休计划在制度切换前后的可比性；完成后才能形成第一版跨年稳定规则清单。

## 2023 L1—L3市场历史链复验

2023版L1—L3的2019—2023五年序列已完成逐指标复算。保单数满足`L2非相连 + L3相连 = L1总额`，5个年度全部精确归零；保费最大差异0.1百万元。L3不发布保额，L1的相连保额为`N.A.`，因此保额只能用L2与L1做披露舍入控制，最大差异同为0.1百万元，不能解释为相连保额等于零。

净负债再次证明必须把总表中的两类额外储备纳入公式。只加L2和L3时，2019—2023分别残留23,525.3、31,796.0、37,042.3、14,378.9和104,538.1百万元；加入L1非相连及相连额外储备行后，五年均在0.1百万元披露舍入范围内闭环。Agent必须把这些储备行建成可追溯事实，不能因行标签简略而丢弃。

进一步比较2023版与2024版L1，对重叠的2020—2023四个观察年度、保单数/保费/保额/负债四项指标共16个单元格，官方值全部完全一致。这同时验证了两个时间字段必须分开：`report_year`表示文件版本，`observation_year`表示表内历史期。当前L1—L3关系已完成两个报告版本复验，状态升级为`validated_2_of_3`，仍需第三个年度包才能晋升为稳定规则。

下一步继续复验2023的L4、L6、L7，重点判断跨粒度控制在旧制度下是否仍成立，以及L7“其他业务”是否需要独立版本化业务节点。

## 2023 L4跨粒度复验

2023年L14、L15、L16均动态识别出59家公司，四项指标的公司明细汇总与第70行市场总额完全一致，共12个控制值无差异。将公司表的千元转换为L4的百万元后，L4与三张公司表的保单数全部精确一致：非相连859,222份、相连33,095份、全部个人人寿892,317份。

金额控制需要显式处理披露精度。2023年L4只显示到0.1百万元，公司表保留千元：非相连总额差0.052百万元；相连年付和整付分别差0.072及-0.021百万元；最终总额差0.103百万元。总额略高于0.1并非异常，而是多个已舍入组件加总后的累计边界。因此Agent不能为所有控制硬编码一个固定0.1容差，应依据源精度和参与加总的组件数量生成容差上限。

业务粒度边界与2024一致：L4非相连按分红属性拆分，只能与L14在总额粒度对账；L4相连与L15共享年付/整付维度，可以逐项对账。列序则不同——2023公司表年付在前、整付在后，2024相反——再次验证标签映射规则。

由此，`L4 → L14/L15/L16`跨粒度关系完成2023、2024两个年度复验，升级为`validated_2_of_3`；稳定的是连接图、共同维度与单位换算，版本化的是列序和披露精度。下一步复验2023 L6团体及退休计划控制。

## 2023 L6团体及退休计划复验

2023年的L6结构与2024不同：旧制度只有L6a团体人寿有效业务和L6b退休计划业务，没有L6c非退休团体新造业务。因此2023只能连接L10和L11；同年的L18是相连个人年金新造业务，若仅凭表号把它接入L6，会形成严重的跨业务误连。

59家公司汇总复算显示，L10的保单数、受保人数、保额、年付保费、净负债5项指标，以及L11的保单数、受保人数、年付供款、净负债4项指标，均与各表第70行市场总额完全一致。转换为百万元后，L6a/L6b的数量指标精确归零，金额差异介于0.012至0.080百万元，符合L6类别组件混合使用0.1和0.001百万元精度、公司表保留千元精度所形成的舍入边界。

数量语义发生了明确的制度切换：2023年退休计划披露5,614份保单及2,001,220名受保人；2024年这两项为`N.A.`，改为披露365,637个计划。保单数、受保人数、计划数必须是三个独立`metric_id`，不能构造一条连续数量时间序列。

由此，L6控制图被拆成两层：稳定候选核心是`L6团体/退休有效业务 → L10/L11`，已在2023和2024通过；2024新增分支是`L6c非退休团体新造 → L18`，目前仅验证一期。下一步复验2023 L7，重点处理“年金及其他业务”范围和L17/L18/L19旧制度年金链。

## 2023 L7年金及其他业务复验

2023年L12、L17、L18、L19各59家公司明细均与第70行市场总额完全一致，四张表、每表四项指标共16个控制值全部归零。L7a总额与L12的保单数精确一致；保费差0.018百万元，净负债差0.106百万元，符合多个0.1百万元类别加总后的披露舍入边界。L7b与L19的年付、整付保单数精确一致，两项保费差分别为-0.044及0.043百万元。

此次复验还记录了一次重要的解析失败模式：L7b横轴是非相连/相连，纵轴是整付/定期缴付。如果Agent先取“总数行”再把它解释为年付，会把52,118份总保单错当成年付保单；正确做法是先解析两条维度轴，再按缴费方式跨相连属性加总。该错误不会触发文件读取失败，却会生成看似合理的错误事实，因此已加入Parser验收规则。

控制表路由在制度切换前后发生变化。2023年L12标题为“年金及其他有效业务”，与包含相连年金、永久健康和联合养老保险的L7a全口径对应；新造业务则由`L17非相连年金 + L18相连年金 = L19年金总额`后与L7b对账。2024年L12收窄为年金，L17直接变为个人年金总额，L18改成团体业务。因此稳定的不是固定表号关系，而是“读取年度标题后，将L7连接到同业务范围的公司控制表”。

状态语义也必须保留：2023相连有效年金为非零，团体年金为明确零，永久健康与联合养老保险为非零；2024这些扩展类别多为`N.A.`。不能为了构造连续序列把非零、零和不适用压成同一状态。

至此，2023年L1、L4、L6、L7市场业务控制已全部复验。下一步应汇总第一版跨年规则清单，把规则正式分成稳定候选、年度Schema规则和禁止推断三层，再决定是否引入第三个年度包完成晋升。
