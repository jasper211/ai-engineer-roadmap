## 二、最常用的 4 类查询（已实测可用）

### Q1 · 市场整体趋势（标准事实层 market_facts）
```sql
SELECT period, metric_id, value, unit
FROM market_facts
WHERE metric_id='NB_IND_TOTAL_ANNUALIZED_PREMIUM'   -- 个人新造年度化保费
ORDER BY period;
```
其他常用 metric_id：
- NB_IND_TOTAL_SINGLE_PREMIUM / NB_IND_TOTAL_ANNUALIZED_PREMIUM（个人新造整付/年化）
- NB_GROUP_* （团体新造）
- IF_IND_TOTAL_POLICIES / IF_IND_TOTAL_SUMS_ASSURED_OR_ANNUITIES（个人有效）
- IF_RETIREMENT_*（退休计划）
完整 18 指标见 `schema_metrics` 表。

### Q2 · 年度公司排名（年度公司层 company_facts）
```sql
SELECT insurer_name_source, value_raw
FROM company_facts
WHERE report_year=2024 AND table_id='L16'      -- L16=个人新造总额
  AND metric_sem='premium_single'
  AND entity_scope='insurer'
ORDER BY value_raw DESC LIMIT 10;
```
- L8-L13 = 有效业务；L14-L19 = 新造业务
- metric_sem：premium_single/premium_annual/policy_count/current_estimate/net_liabilities 等

### Q3 · 2025 公司级（2025provisional 公司层）
```sql
SELECT insurer_name_en, value
FROM provisional_company_facts
WHERE metric_sem='nb_total_single_premium' AND entity_scope='insurer'
ORDER BY value DESC LIMIT 10;
```

### Q4 · 行业财务/资产配置（财务层 financial_facts）
```sql
SELECT item_label_zh, value_hkd_million
FROM financial_facts
WHERE period='2026Q1' AND fund_scope='long_term'
  AND item_id IN ('debt_securities','equities_portfolio','cash_and_deposits')
ORDER BY value_hkd_million DESC;
```
- fund_scope：industry_total / long_term / participating_long_term / general_business

## 三、口径约定（务必遵守，避免 U20 误用）

| 约定 | 说明 |
|---|---|
| **金额单位** | 财务层=`HKD_million`；年度层/2025层/标准层=`HKD_thousand`(千港元)。单位按各自表字段声明为准 ⚠️ 不混加 |
| **count vs 金额** | 保单数/受保人数/计划数=count，与金额字段不混加 |
| **certified vs provisional** | ①年度公司层(2022/2023/2024)=certified；②标准季度层、2025provisional层、财务层=provisional。⚠️ **季度数据(2023Q1/2024Q1等)一律是 provisional，绝非 certified**；勿把年度层标签套到季度层 |
| **schema 切换** | 2024Q3 起 RBC（分红/其他/相连）；pre-RBC（A-F类别）。跨 schema 同环比需 bridge |
| **公司改名/转让** | 安盛/萬通/周大福/安達、Canada→MyPace 在 identity/lineage 桥承接；勿把转让当自然增长 |
| **L11 退休计划** | 2022/23=L11 保单数+lives；2024=L11 scheme_count |
| **year(季度) axis** | 标准事实层用 `period`(如 2023Q1)；年度层用 `report_year` |

## 四、U20 调用建议

### 4.1 推荐入口
- **首选**：标准事实层（Q1）+ 年度公司层（Q2）+ 财务层（Q4）三库组合，覆盖市场/公司/财务三维。
- 需 2025 当年公司口径时，加 2025provisional 公司层（Q3）。

### 4.2 若需"公司维度 + 年度连续性"（已修正跨库写法）
> ⚠️ SQLite 不能用 `db文件名.表名` 直接引用另一库的表。正确做法是**独立连接**或 **ATTACH**。

**方法 A · 独立连接（推荐，最稳，只读）**
```python
import sqlite3
# 用 mode=ro 只读 URI 打开，避免误写源库
ann = sqlite3.connect('file:.../annual_company_fact_layer_2022_2024.db?mode=ro', uri=True)
prov = sqlite3.connect('file:.../annual_provisional_company_2025.db?mode=ro', uri=True)
rows24 = ann.execute("SELECT insurer_name_source, value_raw FROM company_facts WHERE report_year=2024 AND table_id='L16' AND metric_sem='premium_single'").fetchall()
rows25 = prov.execute("SELECT insurer_name_en, value FROM provisional_company_facts WHERE metric_sem='nb_total_single_premium' AND entity_scope='insurer'").fetchall()
# 两段结果在应用层按公司名/key 关联（注意 scope 差异，勿直接拼成增长）
```

**方法 B · ATTACH（只读，SQL 层跨库 join）**
> ⚠️ 不能用 `(READ ONLY)` 后缀（语法报错 `near "ONLY"`）；须用 `mode=ro` URI 附加。
```python
import sqlite3
conn = sqlite3.connect(':memory:', uri=True)
conn.execute('ATTACH DATABASE ? AS ann', (annual_path.resolve().as_uri() + '?mode=ro',))
conn.execute('ATTACH DATABASE ? AS prov25', (provisional_path.resolve().as_uri() + '?mode=ro',))
conn.execute('PRAGMA query_only=ON')
rows = conn.execute("SELECT ... FROM ann.company_facts WHERE report_year=2024 AND table_id='L16'").fetchall()
rows2 = conn.execute("SELECT ... FROM prov25.provisional_company_facts WHERE metric_sem='nb_total_single_premium'").fetchall()
```
> ⚠️ **口径警示**：2024 `L16` = 个人**寿险**新造；2025 `L1` 总额 = 个人**长期(含年金/相连)**。两者 scope 不同，**不能直接算同口径同比增长**。跨库公司拼接须先过 identity/lineage 桥。
> 注：本指引历次修正——先修 `FROM xxx.db.table`（非法），再修 `ATTACH ... (READ ONLY)`（语法错误），现用 `mode=ro` URI。

### 4.3 性能/稳定性
- 各 DB 为只读 SQLite，可直接连接；查询秒级返回。
- 建议用只读连接（`sqlite3.connect('file:...?mode=ro', uri=True)`）防止误写。

## 六· 补充：跨年度同口径增长（2024 vs 2025）— ⚠️ 尚未验收

> 详见 `生成_跨年度同口径桥_CrossYearBridge/`。

⚠️ **2024 L16（个人寿险）与 2025 L1（个人长期）口径不同，不能直接算增长**（2025 L1 含年金混入）。

**当前状态：`+65.4%` 为「待验证的异口径试算」，NOT 已验收的市场同口径增长，请勿当作可信发布区间放行。**

原因（据 U20 复验 r2）：
- 剔除 2025「其他」档 **不能自动证明**剩余集合=2024 L16，缺双向范围等价证明。
- 「1492.0亿 分红+相连」分项未独立复算验收。
- 公司增幅大/小不能单独证明自然增长 vs 业务转让 vs 重分类。

**可用于参考（非发布）**：2024 L16 整付 902.3亿 → 2025 分红+相连子口径 1492.0亿 → 试算 +65.4%（含年金则 +79.6%）。
**公司级**：多数公司可参考，但 TPLHK/Chubb/SunLife/AXA 有大额异常，**不得直接发布增长率**，需业务事件复核。

> 范围等价证明与机器可读桥补齐前，撤回「同口径增长可发布」放行措辞。
