## 二、仍未通过的事项

### 1. ATTACH示例仍有语法错误

指引4.2方法B：`ATTACH '...' AS ann (READ ONLY);` 在当前SQLite实测报错：`near "ONLY": syntax error`。

已用真实两库验证可行写法：在启用URI的连接上，用 `mode=ro` URI附加数据库，不使用 `(READ ONLY)` 后缀。例如Python：

```python
conn = sqlite3.connect(':memory:', uri=True)
conn.execute('ATTACH DATABASE ? AS ann', (annual_path.resolve().as_uri() + '?mode=ro',))
conn.execute('ATTACH DATABASE ? AS prov25', (provisional_path.resolve().as_uri() + '?mode=ro',))
conn.execute('PRAGMA query_only=ON')
```

附加后实测行数7,097 / 414。此片段假设已导入sqlite3，两个path为指向真实库的Path对象。指引方法A还把Python连接语句放进SQL代码块，且未使用只读参数；不宜直接当可执行SQL复制。

### 2. “+65.4%同口径增长可发布”证据不足

新增方案比较2024完整L16与2025“分红+相连”子集。剔掉2025“其他”一档，**并不能自动证明剩余集合等于2024 L16**。仍需双向证明：是否剔除了2024口径应保留的寿险业务、是否剩余类别仍含2024口径之外的业务。

数据库复算确认：2024 L16为90,226,978.423197千港元，L17为4,784,506.4147千港元；2025个人长期总额为162,006,264.85723746千港元。2025公司库当前仅存新造总额指标，未包含可直接复算“分红+相连”分项的事实记录；本轮没有重新读取原始工作簿，因此**1492.0亿的分项抽取亦未独立验收**。

即便算式成立，也不能替代范围等价证明。“+65.4%”最多先记为待验证的异口径试算，不应标为已验收的市场同口径增长，更不是统计意义的可信区间。公司增幅大小也不能单独证明自然增长、业务转让或重分类；不能只阻断异常公司，就默认其余公司同口径通过。
