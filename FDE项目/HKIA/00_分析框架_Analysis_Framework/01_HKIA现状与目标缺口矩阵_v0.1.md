# HKIA 现状与目标缺口矩阵 v0.1

## 1. 总体判断

当前 HKIA 已经具备较好的“监管 Excel → 统一长表 → 确定性聚合”能力，但离完整行业分析系统还有三次跃迁：

1. 从单一监管数据源跃迁为多源行业情报系统；
2. 从数据处理跃迁为证据与命题治理；
3. 从单体解析 Agent 跃迁为有阶段门的分析 Agent 协作系统。

## 2. 分层缺口

| 层 | 目标能力 | 当前已有 | 主要缺口 | 状态 |
|---|---|---|---|---|
| L0 决策/主题 | Theme Universe、问题路由、使用者 | 单个分析需求 | 没有完整主题地图与优先级 | 缺失 |
| L1 来源策略 | 多源目录、来源能力边界 | IA官网Excel | 未纳入公众号、行业网站、专家、公司披露、内部经验 | 缺失 |
| L2 采集 | 手动+自动+监测 | 手动下载 | 自动下载、网页监测、RSS/API、失败重试未建 | 局部 |
| L3 来源登记 | Source Registry、快照、哈希、权限 | 文件名和source_report | URL、作者、发布日期、版本、原文快照不完整 | 薄弱 |
| L4 解析标准化 | 表格+文本+图片统一解析 | Excel双引擎、schema标记 | 网页、公众号、PDF、动态、图片信息图解析未建 | 局部 |
| L5 证据/事实 | Fact、Evidence Card、冲突管理 | SQLite事实表 | 没有证据卡、观点类型、冲突与可靠度 | 局部 |
| L6 Spec合同 | 时间、口径、维度、颗粒度 | 培训材料+首题合同 | 未正式配置化；未绑定实际事实表 | 薄弱 |
| L7 分析引擎 | 三镜、边际、量价、Peer等 | growth/ranking技能 | 模型路由、统一输出Schema、反事实不足 | 局部 |
| L8 命题知识 | A/B/C、反证、经验显性化 | 单页中手工标注 | Claim Registry、经验卡、证据升级路径未建 | 缺失 |
| L9 报告 | 多类型交付、全链路溯源 | HTML demo、Probe单页 | 页面合同、来源注脚自动化、报告版本体系未建 | 局部 |
| L10 Agent系统 | 多角色、状态机、Gate、日志 | Excel解析Agent | 角色未拆、分析Planner/Challenger/Reviewer未实现 | 缺失 |
| L11 治理评估 | 回归、异常、评分、方法转正 | 9项集成测试 | 内容质量、证据完整性、Agent过程评估不足 | 局部 |

## 3. 现有资产应保留什么

- 45期原始 IA Excel 作为第一个监管事实源。
- `long_term_business` 统一长表及七类 `table_type`。
- `pre_rbc/post_rbc` schema 分界。
- 文件发现、Excel解析、标准化、增长和公司排名技能。
- 真实踩坑记录及9项集成测试。

这些不是完整系统，但已是后续 Source/Fact/Data Steward 能力的可靠种子。

## 4. 当前最危险的错觉

| 错觉 | 实际问题 |
|---|---|
| 有45期数据就有行业知识 | 数据主要证明结果，不证明客户和经营机制 |
| 增加更多网页就能提高质量 | 没有来源和证据治理，只会增加不可核验文本 |
| 一个强提示词就是分析Agent | 缺少阶段门、事实绑定、反证和评估 |
| 报告好看说明系统成熟 | 页面可能掩盖口径错误和证据越级 |
| 老板经验接入后可直接当真 | 经验也需要情境、例证、反例和版本 |

## 5. 当前优先级

### P0：没有就不能安全扩展

1. Theme Universe 与问题路由。
2. Source Registry 与来源分类。
3. Fact/Evidence/Claim 三类核心对象 Schema。
4. Spec Registry 与阶段门。
5. 全过程运行日志。

### P1：提高分析解释力

1. 公众号/行业网站/专家动态摄入。
2. 公司披露与监管事件时间线。
3. 平行证据与冲突观点处理。
4. Challenger 和 Reviewer 角色。

### P2：提高自动化与规模

1. 自动下载与监测调度。
2. 增量更新、去重和告警。
3. 报告自动编排与Dashboard。
4. 方法论规则自动转正辅助。
