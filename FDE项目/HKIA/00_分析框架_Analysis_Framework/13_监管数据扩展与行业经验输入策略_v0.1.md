# 监管数据扩展与行业经验输入策略 v0.1

> 依据：2026-08-03对IA官网与data.gov.hk当前公开栏目进行覆盖审计。目标是按Theme缺口扩充，而非一次性下载全部资料。

## 1. 结论

当前45期长期业务季度数据只覆盖监管公开数据的一部分。IA还公开年度长期业务L1-L19、中介牌照、投诉/Conduct in Focus、市场主体、年报及监管资料等。这些来源可以显著提高T02、T20-T22、T30和部分T32的证据覆盖。

但现在不应直接进行全量下载。正确顺序是：

```text
Theme缺口
→ 来源覆盖审计
→ Source登记与权限检查
→ 选定垂直切片
→ Asset采集
→ Fact/Opinion抽取
→ Contract内使用
```

## 2. 可补充的监管数据域

### R1 年度长期业务统计

公开年度数据至少包含：

- L1 个人人寿业务；
- L2/L3 非相连、相连有效业务；
- L4 新造个人人寿；
- L5 自愿终止率；
- L6 团体与退休计划；
- L7 年金及其他业务；
- L8-L19 个别保险公司的有效、新造、年金、团体及总长期业务；
- Notes、公司覆盖名单与术语定义。

补充价值：

| Theme | 新增能力 |
|---|---|
| T02 | 自愿终止率、有效业务和新造到存量的连接 |
| T10 | 更完整产品/业务类型结构 |
| T20 | 公司存量与新造格局并列 |
| T21 | 公司能力与Peer的长期视角 |
| T32 | 只补业务状态代理，仍不能替代利润/资本数据 |

注意：年度表与季度临时统计并非天然同一事实链，必须单独登记Source、口径、发布时间和修订版本。

### R2 中介牌照与队伍统计

IA公开2019年以来的中介牌照统计，包括个人代理、代理业务代表、经纪业务代表、代理机构及经纪公司等。

补充价值：T22中介队伍规模、牌照类型和长期业务资格结构；与渠道份额形成平行证据。

边界：牌照人数不等于活跃代理人数、生产率或留存。不得用牌照统计直接计算人均产能，除非对象和活跃口径得到补充。

### R3 Conduct in Focus与投诉统计

可提供投诉类别、销售行为、代理层级管理、社交媒体推广、年龄画像、流转率和持牌时长等监管观察。

补充价值：

- T22中介队伍结构和行为风险；
- T30监管关注重点；
- T02服务/行为结果的外围证据；
- T12渠道机制的风险与替代解释。

边界：投诉数据是监管收到的案件，不代表全行业发生率；分类可能按主要问题归类，也可能排除公司自报案件。

### R4 市场主体与保险公司资料

包括获授权保险公司数量、业务类别、注册地、公司名单和市场概览。

补充价值：T20公司Universe、Entity Registry、进入退出和公司范围变化。

### R5 IA年报与监管文件

包括监管工作、规则实施、投诉处理、渠道报酬、资本制度和市场发展项目。

补充价值：T30监管事件时间线、T21公司/渠道行为的制度背景，以及T32部分价值链约束。

边界：监管叙事可以证明政策目标和监管行动，不能单独证明市场变化由该政策导致。

### R6 data.gov.hk结构化资源

年度和季度保险数据存在CSV/XLS/XLSX资源，可用于：

- 自动化下载备选；
- 单表增量处理；
- 与IA官网文件交叉验证；
- 降低复杂Excel解析成本。

需要验证：数据更新滞后、资源URL稳定性、与IA修订版的一致性。

## 3. 分批接入建议

### Batch 1：先补分析框架缺口

1. 年度长期业务2024及2019基准年的Notes、L1-L5、L13-L16和公司名单；
2. 2019-2026中介牌照统计；
3. 最新一期Conduct in Focus及投诉定义；
4. 对应data.gov.hk资源元数据。

目标：验证T02/T20/T22/T30能否建立最小Fact链，而不是追求历史全量。

### Batch 2：形成稳定历史线

- 年度长期业务2015-2024；
- 历年中介牌照与投诉；
- RBC及渠道报酬相关监管事件。

目标：建立跨期趋势、断点和事件链。

### Batch 3：按真实问题扩展

- 2001-2014更长历史；
- 一般保险、专项统计和其他非当前Theme数据；
- 新公司披露、宏观与客户数据。

只有在具体Theme/Contract需要时进入。

## 4. 自动化优先级

| 来源 | 当前方式 | 推荐目标 | 理由 |
|---|---|---|---|
| data.gov.hk CSV | 未接 | API/直链自动 | 结构化、适合增量和交叉验证 |
| IA年度/季度文件 | 手动 | 混合模式 | 官网访问挑战、修订版和页面关系需保留 |
| 中介统计网页/附件 | 未接 | 页面监测+附件下载 | 更新频率明确，表格结构相对稳定 |
| Conduct/投诉PDF | 未接 | 页面监测+PDF解析 | 文本与表格并存，需要证据卡 |
| IA年报/监管文件 | 未接 | 事件触发采集 | 重点是事件和规则，不是高频抓取 |

自动化前必须通过Source Registry的权限、快照、重试和失败告警Gate。

## 5. 行业经验何时进入

行业经验不等到Phase F才第一次出现，分四个阶段进入：

### Phase B：小规模种子试点

- 选择T12的一至三条老板/内部经验；
- 建Experience Card，不批量接知识库；
- 只用于问题优先级、机制候选和证据需求；
- 不直接提升公开Claim等级。

目的：尽早验证Experience对象是否好用，避免到最后才发现Schema不合适。

### Phase C：与外部文本并列

- 同一机制同时放入行业媒体、专家观点和内部经验；
- 检查独立证据链、重复转述和冲突；
- 验证Challenger能否识别“大家都这么说”但缺少直接证据。

### Phase D：参与机制验证

- 用公司披露、监管事件和结构化数据验证经验；
- 记录适用情境、反例和失效条件；
- 形成可审阅的B级机制或数据升级计划。

### Phase F：规模化接老板知识库

- 接口、权限、批量Experience抽取和版本治理；
- 比较“公开信息基线”与“加入老板经验”后的命题优先级、解释深度和行动映射；
- 验证经验是否真正提升质量，而不是只让语言更像老板。

## 6. 下一步建议

Phase B先并行推进两个最小切片：

1. **监管数据切片**：年度长期业务L5自愿终止率或中介牌照统计，补当前明确缺口；
2. **经验种子切片**：围绕T12录入一条真实经验，走完Experience → Evidence Link → Claim/Research Question。

这样可以同时验证“新增监管事实”和“行业经验输入”两种质量提升路径。
