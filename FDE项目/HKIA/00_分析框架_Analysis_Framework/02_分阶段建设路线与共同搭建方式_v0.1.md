# HKIA 分阶段建设路线与共同搭建方式 v0.1

## 1. 为什么按“垂直切片”建设

如果先把所有采集器、Agent和目录搭完，容易得到空架子。每一阶段应选择一个真实主题，贯穿来源、证据、分析、页面和复盘，但本阶段只建设必要能力。

## 2. 建设阶段

### Phase A：分析元模型与治理骨架

目标：先规定系统里有哪些对象，以及它们如何流转。

产物：

- Theme Universe；
- Source Registry Schema；
- Fact / Evidence / Claim Schema；
- Spec Registry；
- Agent Run Log；
- Gate 与 DoD。

验收：任意一条结论都能回答“来自哪里、用什么口径、支持哪个命题、谁签核、什么会推翻”。

### Phase B：监管结构化数据切片

目标：将现有 IA Excel 能力纳入新元模型，而不是重写解析器。

产物：

- 45期来源登记；
- 事实表与 Source/Fact ID 绑定；
- 时间/口径/渠道 Spec；
- 自动质量检查；
- Probe-01 全过程重跑。

验收：Probe-01 从 Intake 到 Review 的所有中间对象和日志齐全。

并行加入1-3条行业经验种子，以Experience Card形式参与问题优先级和证据需求设计；完整知识库接入仍放在Phase F。

### Phase C：外部文本情报切片

目标：接入一种行业媒体/公众号和一种专家动态来源。

产物：

- 网页/文章采集与快照；
- 实体、事件、观点抽取；
- Evidence Card；
- 同一命题的支持/反对/未知证据矩阵。

验收：外部观点不能直接改写 A 级事实，并能识别二手引用和来源重复。

### Phase D：公司与监管机制切片

目标：引入公司披露、监管文件，构建渠道迁移的机制验证链。

产物：

- 公司动作与监管事件时间线；
- 固定/动态 Peer；
- B级机制与替代解释；
- 证据升级清单。

验收：报告能明确区分“发生了什么”“可能为什么”“还需查什么”。

### Phase E：Agent 角色化与自动运行

目标：将已验证的人机动作拆为 Agent 能力。

产物：

- Source Scout、Data Steward、Planner、Analyst、Challenger、Composer、Reviewer；
- 状态机、熔断、人工 Gate；
- 回归测试与成本/时间记录。

验收：Agent 不能绕过合同直接出报告；失败能退回正确协议层。

### Phase F：老板知识与方法论融合

目标：把老板知识库和经验变成可验证、可更新的知识资产。

产物：

- Experience Card；
- 阈值/案例/反例；
- 经验支持的命题和适用情境；
- 与公开证据冲突时的处理规则。

验收：能够清楚比较“仅公开信息”与“加入老板经验”后，哪些命题、优先级和行动建议发生变化。

## 3. 每一小步的共同搭建记录

以后每次推进都固定展示：

1. **本步目的**：消除什么不确定性；
2. **输入**：使用了哪些现有资产；
3. **设计选择**：有哪些方案，为什么这样选；
4. **产物**：新增或修改哪些对象/文件/代码；
5. **验证**：如何证明它工作；
6. **人工判断**：哪些地方由 Jasper 决定；
7. **暴露缺口**：下一层缺什么；
8. **转正候选**：哪些动作可能成为 Skill/Agent 规则。

## 4. 下一项建议：先建 Theme Universe

原因：来源策略、数据需求和 Agent 路由都依赖主题边界。没有 Theme Universe，就无法判断应该监测哪些公众号、专家和公司，也无法判断“资料更多”是否真正补充了分析问题。

首轮 Theme Universe 不追求一次完整，而是先回答：

- 香港长期险有哪些稳定主题域；
- 每个主题域的决策问题是什么；
- 主维度、必需证据、可用来源和不可证明项是什么；
- 主题之间如何链接；
- 哪些主题优先进入 Agent 化。

## 5. Probe-01 的处理

已生成的代理渠道单页保留，但状态改为：

`early_probe / not_framework_complete / not_for_decision`

后续在 Phase B 完成后，用完整运行链重新生成 v1.0，并对比两版之间新增了哪些过程资产和质量控制。
