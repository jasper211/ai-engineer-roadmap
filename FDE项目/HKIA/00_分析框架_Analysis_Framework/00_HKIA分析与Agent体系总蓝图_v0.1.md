# HKIA 分析与 Agent 体系总蓝图 v0.1

> 文档定位：定义 HKIA 从多源输入到分析交付、再到方法论沉淀的完整目标架构。它不是报告目录，也不是某个 Agent 的提示词。

## 1. 项目重新定位

HKIA 的目标不是“把 IA Excel 做成图表”，而是建立一个可重复的行业分析系统：

> 多源行业信息持续进入，经来源与证据治理形成统一事实底座；分析任务继承统一 Spec，经过事实、机制、反证与页面验收；执行过程被 Agent 记录、评估并沉淀成可复用能力。

本项目同时建设四类能力：

1. **信息获取能力**：监管、行业媒体、专家动态、公司披露和内部知识持续进入。
2. **证据治理能力**：区分事实、观点、推断和内部经验，保证来源、时间和适用边界可追溯。
3. **分析能力**：使用统一时间、口径、维度、逻辑链和证据等级回答业务问题。
4. **Agent执行能力**：让可确定动作自动化，让关键业务判断保留人工 Gate，并记录全过程。

## 2. 三套结构必须分开

| 结构 | 核心问题 | 主要产物 |
|---|---|---|
| 分析框架 | 应该问什么、如何证明 | Spec、主题卡、命题树、DoD |
| 情报与数据流水线 | 信息如何进入并成为证据 | Source Registry、原文、事实表、证据卡 |
| Agent运行系统 | 谁在何时执行什么动作 | 状态机、工具、人工Gate、日志、评估 |

三者关系：流水线提供可用证据，分析框架约束如何使用证据，Agent 系统负责按约束执行并留痕。

## 3. 十二层目标架构

### L0 决策与主题层

- 定义读者、决策动作、问题边界和成功标准。
- 建立 HKIA Theme Universe：市场规模、产品、缴费、渠道、币种、客户/地域、公司、业务质量、监管等。
- 一个任务只选择一个主解释轴，可配置平行验证轴。

### L1 来源策略层

来源不是越多越好，而是明确每类来源能证明什么：

| 来源域 | 示例 | 主要价值 | 固有限制 |
|---|---|---|---|
| 监管结构化数据 | IA Excel、data.gov.hk | A级规模、结构、份额 | 难证明动机与经营动作 |
| 监管非结构化信息 | 通告、咨询文件、新闻稿 | 制度变化、事件时间线 | 影响需另行验证 |
| 公司披露 | 年报、业绩会、产品/渠道公告 | 公司策略与经营解释 | 选择性披露、自述偏差 |
| 行业媒体/公众号 | 保险行业公众号、专业媒体 | 事件、案例、市场解释 | 二手信息、口径不透明 |
| 专家动态 | LinkedIn、行业大咖文章/演讲 | 机制假说、趋势信号 | 观点不等于事实 |
| 内部知识 | 老板知识库、会议、经验判断 | 阈值、语境、历史案例、行动映射 | 需显性化并记录适用范围 |

### L2 采集层

- 手动上传、自动下载、RSS/API、浏览器读取、页面监测、邮件/消息转存。
- 每个采集器输出统一采集清单，不直接生成分析结论。
- 自动化下载要处理版本、重复、失败重试、访问限制和合规边界。

### L3 原始资料与来源登记层

- 原始文件只追加、不覆盖。
- 每项资料生成 `source_id`，登记 URL/路径、作者、发布日期、采集时间、来源类型、版本、权限和哈希。
- 保存原文快照，避免网页更新后无法复核。

### L4 解析与标准化层

- 表格：sheet、行列、单位、期间、YTD、schema 版本。
- 文本：标题、段落、引用、实体、事件、指标、观点。
- 图片/信息图：先抽取可核对事实，再记录视觉语义；不得把图中文字直接当成已验证事实。
- 公司、渠道、产品、币种和时间使用统一实体/维度字典。

### L5 证据卡与事实底座层

同时维护两类对象：

1. `Fact`：可复算的数值、事件或明确披露。
2. `ClaimEvidence`：支持或反对某个命题的原文、观点或机制线索。

每张证据卡至少包含：来源、期间、对象、原文/数值、口径、证据类型、可靠度、支持命题、冲突证据和适用边界。

### L6 Spec 与分析合同层

- L0 数据颗粒度与 SSOT。
- L1 时间/Baseline、NOP/APE、份额与边际公式。
- L2 业务维度 Spec。
- L3 公司实体与 Peer Spec。
- L4 合法二维白名单。
- L5 主题与页面合同。

主题不能突破底层数据颗粒度，多个二维事实不能拼成伪三维。

### L7 分析执行层

标准动作链：

```text
决策问题 → 协议路由 → 事实底座 → 三镜 → 边际/对标
→ 逻辑链 → 根因树 → 证据分级 → 反证 → 页面
```

分析模型按问题调用，不默认堆叠：结构/趋势/比率、量价、贡献桥、固定/动态样本、Peer、集中度、事件研究等。

### L8 命题与知识层

- 命题分 A/B/C，而不是给整份报告笼统评级。
- A：来源事实直接证明。
- B：多项事实方向一致，支持机制但需要替代解释。
- C：需要客户、内部经营或利润数据验证。
- 老板经验进入后也要变成显式命题：适用情境、历史案例、反例、阈值和验证数据。

### L9 报告与交付层

- 分析卡、单页、专题、公司深潜、Dashboard 和监测预警。
- 每张图对应一个 Insight，跨图综合回答主题。
- 页面标题继承命题等级，不能比证据更确定。
- 页面数字可反向定位到事实表和来源。

### L10 Agent 协作与运行层

初步按职责拆分，不急于一次开发完：

| Agent角色 | 职责 | 不负责 |
|---|---|---|
| Source Scout | 发现、下载、监测来源 | 判断业务结论 |
| Ingestion Agent | 解析、标准化、实体映射 | 修改原始资料 |
| Data Steward | 公式、质量、断点、SSOT | 替代业务解释 |
| Analysis Planner | 问题卡、Spec路由、证据需求 | 自行签核决策目的 |
| Evidence Analyst | 三镜、边际、命题证据包 | 把C级写成事实 |
| Industry Challenger | 替代解释、反证、缺失信息 | 编造行业经验 |
| Report Composer | 图文组织、页面合同 | 改写数据边界 |
| Reviewer/Evaluator | DoD、异常、回归与评分 | 对最终业务判断负责 |
| Methodology Curator | 从案例中提取稳定规则 | 一次案例就宣布通用 |

早期可以由同一个 AI 终端扮演多个角色，但日志和责任必须分开。

### L11 治理、评估与进化层

- Source、Metric、Entity、Claim、Spec、Prompt 和报告均有版本。
- 确定性检查优先；关键数字用独立来源或原表抽查。
- 保存失败、返工、人工修改和熔断记录。
- 同一规则至少跨三个案例验证后，才进入模板、Skill 或 Agent 正式能力。

## 4. 两条并行流

### 证据流

```text
Source → Raw Asset → Parsed Record → Fact/Evidence Card
→ Claim → Insight → Page → Published Artifact
```

### 执行流

```text
Intake → Contract → Source Plan → Data/Evidence Ready
→ Analysis → Challenge → Compose → Review → Publish → Retrospective
```

报告质量取决于两条流是否在每个节点相交：没有来源的判断不能进入命题，没有合同的事实不能直接进入页面。

## 5. 当前案例如何使用

已制作的“代理规模增长但未跑赢市场”单页降级为 **Probe-01 早期探针**。它的价值不是作为完成品，而是暴露框架缺口：

- 已验证：结构化监管数据足以支持 A 级渠道事实。
- 已暴露：百分比显示、schema 断点和整付字段需要确定性规则。
- 尚缺：来源策略、文本证据卡、外部观点冲突处理、完整主题地图、角色化 Agent 日志和报告评分体系。

## 6. 建设原则

1. 先定义对象与合同，再开发 Agent。
2. 先做来源与证据治理，再做“自动摘要”。
3. 每增加一种来源，都先定义它能证明什么和不能证明什么。
4. 每增加一个 Agent，都必须有输入、输出、熔断、人工 Gate 和评估方法。
5. 报告只是系统运行的一次结果；过程资产和可复用规则同样是交付物。
