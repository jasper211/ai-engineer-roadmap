# S9_代理人与KA业务 · 反推标准（v0.1，用真实数据核验）

> S9共346行，10个顶层板块(A-J)，其中H/I/J各含6张周度子表(预约/签单/批核 × APE/件数)。
> 全部关键规则已用真实数字核验。

## 一、关键规则

### 1.1 A节 = S2-A同一份业务细分年度汇总，只取5条"代理人"业务线
天领业务/成事家办/合伙转介业务/ICLUB业务/IFA业务——不含BK业务/同行经代/永明经代（这3条是
"机构渠道"业务线，S9范围是纯代理人+KA业务）。口径跟S2-A完全一致，直接复用
`S2BusinessViewBuilder.segment_summary(carrier=None)`的结果，过滤+重新汇总"合计"行。
用5条业务线目标APE精确验证：193M+70M+73M+52M+25M=413M，跟报表"合计"目标APE一致。

### 1.2 B/C/F节的KA汇总 = 单一segment过滤 + 按key_account分组统计，同S2-K/O规则
排序按2026批核APE降序；遇到2026批核APE完全相等的并列（如B节"苏州贴牌"vs"厦门贴牌"均为
273000），用总APE(合计APE)降序作二级排序——只有1个真实并列样本验证，低置信度，不排除
还有其他二级/三级排序键未被触发。

### 1.3 D/E/G节标题"(含流失单)"具有误导性——实测口径跟S2月度趋势的res/sign/issue三态完全一致
标题写"含流失单"，但精确核验多组真实数字后发现：预约=排除流失类(3态)、签单=排除流失类+排期、
批核=仅生效，跟S2的`monthly_trend`函数逻辑完全相同，不是真的把流失单据算进去。
D/E/G节的月份范围固定是2026-01到2026-08（不是全年12个月），跟当前数据实际覆盖范围一致。

### 1.4 H/I/J节的KA周度明细：排序规则="该表自身列合计APE/件数降序"，不是按业务细分固定顺序
每张子表(预约APE/预约件数/签单APE/签单件数/批核APE/批核件数)各自独立：
- 独立计算周(`%YW%U`，跟S3完全一致)
- 独立过滤"该指标下贡献为0"的KA（同一KA可能出现在批核子表但不出现在预约子表，
  如"长沙贴牌"只在批核APE/件数子表出现，因为它唯一一条2026年记录直接是"生效"状态，
  没有落入2026年的预约/签单窗口）
- 独立按自身合计值降序排序，不跟随其他子表或segment_code固定顺序
