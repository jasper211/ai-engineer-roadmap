# ICD 生产运行手册

## 推荐年度披露更新流程

```bash
python3 04_定义Agent_Define_Agent/agents/agent.py --validate-config
python3 04_定义Agent_Define_Agent/agents/agent.py --health
SSL_CERT_FILE=/etc/ssl/cert.pem python3 04_定义Agent_Define_Agent/agents/agent.py --run-all
python3 04_定义Agent_Define_Agent/agents/agent.py --health
python3 04_定义Agent_Define_Agent/agents/agent.py --analyze
```

披露属于年度数据，默认过期阈值为 400 天；可用 `--max-age-days` 调整。联网运行完成后必须再次执行健康检查，只有数据库、证据快照和业务关联均未出现完整性故障，才更新分析报告。

## 健康状态与自动化决策

- `HEALTHY` / 退出码 0：完整性正常，且所有已登记覆盖项为 FULL、数据未过期。
- `DEGRADED` / 退出码 1：系统完整性正常，但存在 BLOCKED、MISSING、UNVERIFIED 或数据过期。允许读取已有数据，下游必须展示缺口。
- `CRITICAL` / 退出码 2：数据库损坏、外键违例、业务孤儿、重复自然键、快照缺失或 SHA-256 错配。立即停止发布和下游刷新。

当前基线为 `DEGRADED`，原因是已知覆盖缺口，不是数据损坏。任何自动调度器都应保留命令的 JSON 标准输出和退出码作为任务日志。

## 故障处理

1. `CRITICAL` 时不要删除或覆盖数据库、快照；先复制现场并记录健康检查 JSON。
2. 快照缺失或哈希错配时，按 `run_id` 反查官方 URL，不允许用第三方文件替换。
3. 单源结构漂移时维持旧成功版本、降低 coverage，并更新对应解析 fixture 后重跑全量回归。
4. `DEGRADED` 的已知缺口可继续提供已有数据，但报告不得宣称全市场完整覆盖。
