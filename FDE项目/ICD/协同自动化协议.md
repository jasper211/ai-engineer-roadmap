# ICD · 分阶段协同自动化协议

## 角色

- Codex：建设期的项目经理、直接实现方和自审方；维护任务队列、实现、验收证据和重大决策清单。自审必须明确标记，不能冒充异模型独立审计。
- vscode-deepseek：建设期不逐任务参与；在框架与扩展覆盖达到里程碑后执行一次集中独立复核。进入稳定运营期后，负责边界窄、输入明确的增量执行任务。
- Jasper：项目所有者。只处理重大决策 Gate 和最终业务确认。

## Token 与执行效率约束

- 派发前必须确认没有同任务执行会话仍在运行；会话句柄暂时不可用时，先查任务日志、文件时间和运行迹象，不得直接重复派发。
- 执行方只读取当前任务所需文件；除首次接入或协议变化外，不重复通读完整历史日志。
- 开发阶段只跑相关测试，提交前全量回归一次；回执只记录退出码、失败项和汇总，不粘贴逐条成功断言。
- 执行方负责实现与一次简明自证，独立审计由 Codex 完成，不重复做多轮解释性自审。
- 后续任务保持单一交付目标；跨度过大时拆成连续小任务，由 Codex 验收后再派下一项。
- 每个任务验收时必须把会话数、返工轮次、人工 Gate、测试次数、耗时和可取得的 token usage 写入 `11_监控与优化_Monitor_and_Optimize/双模型自动推进案例复盘.md`；usage 不可得时明确写 `unavailable`，不得估算冒充实测。

## 分阶段执行策略

### 阶段 A：建设与覆盖扩展

- Codex 直接实现、测试和维护日志，避免 DeepSeek 重复加载项目历史造成高 token 消耗。
- 每个任务仍须有任务书、允许范围、验收标准、命令、退出码和真实数据证据。
- 采用事件内闭环：同一次执行中完成实现后立即自审，通过后立即生成并开始下一任务，不等待定时轮询触发审计。
- 定时自动化只作恢复看门狗；日志无新状态且没有实际可继续动作时立即结束，不得重复读取、测试或追加无变化回执。
- 达到阶段里程碑后才由 DeepSeek 做一次集中异模型复核；复核只读当前架构摘要、变更范围和验收清单。

### 阶段 B：稳定运营

- Codex 负责监控、派发、差异审计和放行。
- DeepSeek 只执行新增单一来源、修复单一解析器或处理单次异常等窄任务；不得每次重读完整历史。

## 单任务循环

1. Codex 根据上一任务的已验收产物生成唯一下一任务。
2. Codex 在`任务日志.md`登记任务ID、允许修改范围和验收标准。
3. 建设期由 Codex 直接执行；运营期由 DeepSeek 执行并提交简明回执。
4. 建设期由 Codex 自审并明确标注；里程碑和运营期由另一模型独立复核 Git diff、文件范围、确定性测试、真实数据证据和失败语义。
5. 不通过则写具体缺陷及重验条件；执行方只修正缺陷，不自行放宽标准。
6. 通过后 Codex 把状态改为`ACCEPTED`并派发下一任务。

## 审计独立性

- 不把执行方测试作为唯一证据；建设期 Codex 自审须留可复现证据，里程碑由 DeepSeek 集中独立复核。
- 优先使用结构校验、唯一约束、哈希、记录数和已知官网数字等确定性证据。
- 执行方不得编辑 Codex 审计脚本或审计结论，除非返工任务明确授权。
- 网络测试与固定快照测试分开记录；任一方未执行都必须明示。
- 所有状态变化追加到`任务日志.md`，不覆盖历史。

## 执行器约定

认证完成后，Codex通过 DeepSeek CLI 非交互模式派发当前任务。执行提示必须包含：任务书绝对路径、工作目录、允许修改范围、禁止事项和回执位置。不得使用跳过审批的全权限模式。

首次认证 Gate：

```bash
deepseek auth set --provider deepseek
deepseek doctor
```

认证信息只进入 DeepSeek 自己的凭证存储，不写入 ICD 项目，不进入任务日志。
