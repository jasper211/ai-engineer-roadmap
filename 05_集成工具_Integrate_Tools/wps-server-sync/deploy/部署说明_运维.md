# WPS 云文档同步 · 服务器部署说明（运维）

在服务器上部署一个定时任务：每天把 WPS 企业云文档同步成本地完整副本，
供 Syncthing 分发给被授权的人。

**目标机器**：`iZt4n0t5pz9jlq4k3zt26mZ`（Ubuntu 24.04.2 LTS）

---

## 这个程序做什么、不做什么

**做**：调 WPS 开放平台接口，把云端文件下载到指定目录；云端新增→下载，
修改→重下，**删除→本地也删**，保持镜像一致。

**不做**：
- 不修改 WPS 云端任何内容（全部为只读接口调用）
- 不需要 root 运行
- 不需要从外部连入服务器，不开任何端口
- **不消耗 AI token**，是普通 Python 程序

---

## 一、部署（约 5 分钟）

把 `deploy.sh` 和 `wps_mirror.py` 放同一目录，然后：

```bash
sudo bash deploy.sh
```

脚本会完成：

| 步骤 | 内容 |
|---|---|
| 检查依赖 | python3 ≥ 3.9、curl |
| 建运行账号 | `wpssync`（系统账号，**无 sudo 权限**） |
| 建目录 | 镜像目录 `750`，属主 `wpssync` |
| 装官方 CLI | `wps365-cli`，装在 `wpssync` 家目录 |
| 配 systemd | `wps-mirror.service` + `wps-mirror.timer`（**默认不启用**） |
| 配日志轮转 | 按周切割，保留 8 周 |

可用环境变量调整（默认值见脚本顶部）：

```bash
sudo SYNC_USER=wpssync \
     DATA_DIR=/mnt/newdisk/wps-mirror \
     SYNC_ARGS="--only-docs" \
     SYNC_TIME=03:00 \
     bash deploy.sh
```

> **部署脚本不含任何密钥**，跑完也不会开始同步。

## 二、授权（由凭证持有人执行，不是运维）

程序需要一次 WPS 授权才能读取文件。**此步骤涉及企业应用密钥，请由凭证持有人操作**：

```bash
sudo -u wpssync -i
~/.local/bin/wps365-cli auth setup --client-id <APPID>
~/.local/bin/wps365-cli auth login --device --scopes "kso.user_base.read,kso.file.read,kso.file.search,kso.doclib.readwrite,kso.drive.readwrite,kso.file_link.readwrite,kso.dbsheet.read,kso.sheets.read,kso.airsheet.read,kso.airsheet.readwrite"
```

设备码授权：命令行输出一个链接和验证码，**在任意一台有浏览器的电脑上**打开确认，
服务器本身不需要图形界面。凭证存在 `wpssync` 账号下，其他账号读不到。

**有效期 365 天，到期前需重新执行一次 `auth login`。建议加进运维日历。**

## 三、验证（启用定时前必做）

### 1. 试运行 —— 只统计，不下载

```bash
sudo -u wpssync /usr/bin/python3 /opt/wps-sync/wps_mirror.py \
    --mirror /mnt/newdisk/wps-mirror --only-docs --dry-run
```

会输出文件数、总大小、类型分布、各库占比。**确认数字合理再往下走**。

### 2. 手动跑第一次真实同步

```bash
sudo systemctl start wps-mirror.service
journalctl -u wps-mirror.service -f     # 另开一个终端观察
```

首次为全量下载，耗时取决于范围（`--only-docs` 约 40 分钟；全量可能数小时）。
**中断安全**：进度已落 SQLite，再次运行会跳过已完成的文件。

### 3. 确认无误后启用每日定时

**本次实际采用无 root 的 cron 方式**（deploy_user.sh），不是 systemd。
有 root 权限时 deploy.sh 会装 systemd timer，两者取其一。

```bash
crontab -l    # 应看到：0 2 * * * /home/WPSIN/wps-sync/run_sync.sh ...
```

如需重装：

```bash
( crontab -l 2>/dev/null | grep -v wps-sync
  echo "0 2 * * * /home/WPSIN/wps-sync/run_sync.sh >> /home/WPSIN/wps-sync/cron.log 2>&1"
) | crontab -
```

> **不要让 cron 直接调 `wps_mirror.py`。** 必须走 `run_sync.sh`——
> 单实例锁在这个脚本里。首次全量要 6 小时以上，期间 cron 照常触发，
> 没有锁就会起第二个实例，两个进程同时改状态库会互相打乱。

## 四、日常运维

实际部署路径为 `/home/WPSIN/wps-sync/`（非 `/opt`），账号 WPSIN。

```bash
cat  /home/WPSIN/wps-sync/LAST_RUN          # 上次运行结果摘要（推荐先看这个）
tail -f /home/WPSIN/wps-sync/sync.log       # 程序自身日志
crontab -l                                   # 确认定时任务还在
ps -ef | grep [w]ps_mirror                   # 是否有正在运行/卡住的进程
du -sh /mnt/newdisk/wps-mirror               # 占用空间
```

使用方那边还有一个 **`_同步状态.txt`**，在文件夹根目录，每轮自动重写并随 Syncthing 分发。
非技术人员判断系统是否正常，看这个文件的日期即可。

每轮结束会打印汇总：云端文件数、本次下载、跳过、失败、删除、耗时。

### 常见问题

| 现象 | 原因与处理 |
|---|---|
| `拿不到访问令牌` | 授权过期（365 天）或未授权 → 重新执行第二步 |
| 大量 `下载失败` | 多为接口限流 → 程序会退避重试，下一轮自动补；持续出现需确认应用配额 |
| `403 企业套餐权益不足` | 误用了应用身份 → 本方案用的是用户授权，确认授权步骤已完成 |
| 目录没有新文件 | 云端确实没变，或授权账号看不到那些库 |
| 磁盘增长异常 | 检查是否误用了全量模式（含 PDF 与图片约 13.8GB） |
| `[熔断] 本轮将删除 N/M 个文件` | **保护生效，未删任何文件。** 先查扫描为何变少（范围参数？授权？某库列不出目录？），不要直接加 `--allow-mass-delete` 放行 |
| `[跳过] 上一轮同步仍在运行` | 正常。单实例锁在起作用，本轮让路，不用处理 |

## 五、与 Syncthing 的配合

镜像目录即 Syncthing 共享的 folder。程序已做适配：

- **不会删除 `.stfolder` / `.stversions`** —— 清理空目录时跳过点号开头的目录
- **自动维护 `.stignore`** —— 检测到是 Syncthing folder 时，自动加入 `*.part`，
  避免下载中的半截文件被分发出去

建议的 Syncthing 配置：

| 项 | 建议 | 原因 |
|---|---|---|
| 接收端类型 | **Receive Only** | 单向分发；防止有人改本地文件后反向污染 |
| File Versioning | **关闭** | 开启后"云端删除→各端删除"会失效，且持续占空间 |
| 忽略规则 | 含 `*.part` | 部署脚本已自动处理 |

## 六、资源占用参考（实测）

| 项 | 数值 |
|---|---|
| 云端规模 | 22,970 个文件 / 13.78 GB |
| 仅文档表格（`--only-docs`） | 约 1.2 GB |
| 每轮扫描耗时 | **约 23 分钟**（即使无变化也需遍历全部目录） |
| 下载速度 | 约 400 KB/s（单连接），程序默认 4 并发 |
| 首次全量 | `--only-docs` 约 40 分钟；全量数小时 |

程序已设 `Nice=10` 与 `IOSchedulingClass=idle`，优先级低于同机其他业务。

## 七、卸载

```bash
sudo systemctl disable --now wps-mirror.timer
sudo rm /etc/systemd/system/wps-mirror.{service,timer} /etc/logrotate.d/wps-mirror
sudo systemctl daemon-reload
# 数据目录与账号按需保留或删除
```
