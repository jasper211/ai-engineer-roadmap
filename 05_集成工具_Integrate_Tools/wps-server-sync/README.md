# WPS 云文档 → 自有服务器 · 全量镜像同步

在你的服务器上维持一份 WPS 企业云文档的**完整副本**。每轮运行后：
云端新增的会下载、修改过的会重下、**云端删除的本地也删** —— 服务器与云盘保持一致。

## 和「MCP 按需读」的区别

两者互补，不是二选一：

| | 本方案（服务器镜像） | MCP 按需读 |
|---|---|---|
| 文件在哪 | **服务器上有完整副本** | 只在云端 |
| 实时性 | 有延迟（取决于同步频率） | **永远最新** |
| 全文检索 / 离线 | ✅ | ❌ |
| 批量分析 | ✅ 直接读本地 | 每个文件都要过 API |
| 适合 | 批量处理、检索、给其他系统用 | 「这份文件此刻最新是什么」 |

建议两者都留：日常批量读服务器，要确认最新时查 MCP。

## 前置要求

服务器上需要：**python3**、**wps365-cli**、**curl**；推远程还需 **rsync**。
不需要 pip 安装任何包。

```bash
curl -fsSL https://open-docs.wpscdn.cn/cli/install.sh | bash
```

## 授权（一次，管一年）

```bash
wps365-cli auth setup --client-id <APPID>          # 三问：APPKEY / 回车 / 回车
wps365-cli auth login --device --scopes "kso.user_base.read,kso.file.read,kso.file.search,kso.doclib.readwrite,kso.drive.readwrite,kso.file_link.readwrite,kso.dbsheet.read,kso.sheets.read,kso.airsheet.read,kso.airsheet.readwrite"
```

设备码授权，浏览器点一下即可。**refresh_token 有效期 365 天且自动续期**，
之后无人值守运行，中途不需要人干预。

> ⚠️ 授权链接若是 `http://` 开头，手动改成 `https://`，否则页面会不停刷新登不进去。
> 浏览器里必须登录**能看到目标文档库**的企业账号 —— 同步范围完全等于这个账号的可见范围。

### 为什么不用 client_credentials（应用身份）

实测：应用身份调 `/v7/drives/{id}/files/{parent}/children` 返回

```
403 {"code":403000001,"msg":"无权限"}
hint: 企业套餐权益不足。请开通【商业高级版】或【商业旗舰版】；
      这不是 OAuth scope 问题，auth login 或仅在后台开通接口权限无法解决。
```

这是**付费门槛**，申请 scope 解决不了。用户授权同样能无人值守，且不用花钱。
若日后企业升级了套餐，把认证换成 client_credentials 即可，其余逻辑不用动。

## 使用

```bash
# 先看规模：统计文件数、总大小、类型分布、各库占比（不下载）
python3 wps_mirror.py --dry-run

# 只同步文档/表格，跳过图片等（图片常占总量大头）
python3 wps_mirror.py --only-docs

# 只同步指定库
python3 wps_mirror.py --drives "商务结算,佣金管理"

# 完整同步并推送到远程服务器
python3 wps_mirror.py --remote deploy@10.0.1.5:/data/wps-files/ --ssh-key ~/.ssh/id_ed25519
```

### 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--mirror` | `./mirror` | 本地镜像目录 |
| `--remote` | 空 | rsync 目标；留空则只做本地镜像 |
| `--drives` | 全部 | 只同步指定库（drive_id 或库名，逗号分隔） |
| `--only-docs` | 关 | 只要文档/表格类 |
| `--scan-workers` | 6 | 目录遍历并发 |
| `--download-workers` | 4 | 下载并发 |
| `--dry-run` | 关 | 只统计不下载 |

## 定时运行

```bash
# 每天凌晨 2 点
0 2 * * * cd /opt/wps-sync && /usr/bin/python3 wps_mirror.py \
    --remote deploy@10.0.1.5:/data/wps-files/ >> /var/log/wps_sync.log 2>&1
```

## 四个阶段

1. **扫描** — 遍历全部团队库（逐层并发）。串行时每个目录一次往返，实测约 2.3 秒，深目录会慢到不可用
2. **下载** — 只下新增/变更的。判断依据：`version` 变了、`mtime` 变了、本地文件缺失或大小对不上
3. **清理** — 本轮扫描没见到的文件 = 云端已删除，本地一并删除，再清空目录
4. **推送** — `rsync -az --delete` 整个镜像目录到服务器

状态记录在 `sync_state.db`（SQLite）。**中断安全**：进度已落库，下次运行接着来，不会重下已完成的。

## 已验证 / 未验证

**已实测**（真实企业云盘）：

- 扫描 → 下载 → 文件落地，docx 下载后可正常解出正文
- 增量跳过：重跑不重复下载
- 本地文件丢失自动重下
- **云端删除 → 本地删除**（镜像语义）
- 多库遍历、目录层级保持

**未实测**：

- `--remote` 的 rsync 推送（本机没有目标服务器，rsync 命令本身是标准用法）
- 超大规模下的 API 限流表现 —— 见下

## 必须知道的四件事

### 1. API 限流是最大的未知数

每个文件需要 2 次 API 调用（取临时下载地址 + 下载）。上万个文件就是数万次请求。

官方文档称：测试应用 10,000 次/天、**下载接口测试应用仅 500 次/天**；
正式应用分别为 1,000,000 和 100,000 次/天。

**首次全量同步前，务必确认应用已转为正式应用**，否则第一天就会撞墙。
脚本遇到限流会退避重试，仍失败则记录并跳过，下轮自动重试 —— 不会把整轮搞崩。

### 2. 首次全量耗时可能很长

实测单文件下载速度约 **409 KB/s**，每个文件另有约 3 秒取地址开销。
30 GB 在并发 4 的情况下大致需要数小时。建议：

- 先 `--dry-run` 看清规模
- 用 `--only-docs` 或 `--drives` 缩小首轮范围
- 首轮可手动跑、观察日志，稳定后再交给 cron

### 3. 文件落地后，WPS 的权限体系就失效了

云端由 WPS 控制谁能看什么；**同步到服务器后，就只剩服务器的目录权限了**。

这些文件里有保单号、客户姓名、银行账号、身份证号。
「谁能访问这台服务器」等于「谁能看全部内容」，这个边界需要明确由人认领，不是技术能兜住的。

### 4. 扫描件 PDF 同步过去仍然搜不了

扫描件是整页图像，复制到服务器还是图像。要全文检索必须另做 OCR
（可用同项目的 `wps_ocr_mcp.py`，本地识别、内容不出本机）。

## 单向同步

只从 WPS 读，**不会修改云端任何文件**。所有接口调用均为只读（GET）。
