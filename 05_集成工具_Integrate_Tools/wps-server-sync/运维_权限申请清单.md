### sudo 权限

有 sudo 的话可以做**系统级部署**：独立系统账号运行、systemd 定时器、
自动日志轮转、资源限制（不抢占同机其他业务）。

没有也能做：改用**用户级部署**——装在申请人家目录、用 crontab 定时，
完全不碰系统目录。功能一致，只是少了 systemd 的自动重试和资源隔离。

- [ ] 是否可提供 sudo？（可以 / 不可以）

## 三、这个程序会做什么、不会做什么

**会做**：

- 调用金山 WPS 开放平台接口，把企业云文档下载到指定目录
- 每天执行一次（默认凌晨 3 点，可调）
- 云端新增→下载，修改→重新下载，删除→本地也删除，保持镜像一致

**不会做**：

- 不修改 WPS 云端任何内容（全部为只读接口调用）
- 不需要 root 运行（系统级部署仅安装时需要一次 sudo）
- **不开放任何端口，不需要从外部连入**
- 不访问服务器上的其他目录
- 不消耗 AI/大模型额度，是普通 Python 程序

**依赖**：服务器已有的 `python3 3.12`、`curl`，外加一个约 10MB 的官方 CLI
二进制（金山提供，装在运行账号的家目录）。**不需要 pip 安装任何包。**

## 五、预计资源占用

该服务器同时运行 docker 与其他定时任务，以下为本程序的占用评估：

| 项 | 数值 | 说明 |
|---|---|---|
| 磁盘 | 1.2 GB（初期）/ 14 GB（全量） | 位于指定目录 |
| 执行时长 | 首次约 40 分钟；之后每天约 25 分钟 | 每轮需遍历全部目录以发现变更 |
| 执行时段 | 每天凌晨（可指定） | 可与现有 `plaud-sync.timer` 错开 |
| 网络 | 出站访问 `openapi.wps.cn:443` | 平均约 400 KB/s |
| CPU / 内存 | 占用很低 | 系统级部署已设 `Nice=10`、IO 优先级 idle，不抢占其他业务 |

## 六、数据敏感性说明

同步内容包含保单号、客户姓名、证件号、银行账号、合同原件。

同步目录建议权限 **750**（仅属主可读写，其他账号不可访问）。
最终分发范围由 Syncthing 的邀请名单控制，与 WPS 自身权限相互独立。

如需文件级访问审计（auditd 规则），请告知是否方便配置。
