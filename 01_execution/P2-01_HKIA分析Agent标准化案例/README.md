# P2-01 HKIA 分析 Agent 标准化案例

> 案例定位：以 HKIA 为真实测试场，共同搭建“多源输入 → 证据治理 → 分析框架 → Agent协作 → 报告交付 → 方法进化”的标准体系。单个分析题只是验证切片，不是项目终点。

## 1. 为什么做这个案例

本案例不是单纯产出一份香港保险分析，也不是先开发一个 Agent。它有两个并行目标：

1. **业务目标**：形成一页可复算、可证伪、可讨论的 HKIA 渠道分析。
2. **工程目标**：识别哪些分析动作可以标准化、哪些必须保留人工判断、哪些需要确定性校验。

核心原则是“先有人机协同跑通，再抽象 Agent”，避免把尚未验证的个人习惯直接固化成自动化流程。

## 2. 首个训练命题

> 在香港新造个人长期险市场中，2019—2025 年代理渠道绝对业务增长但市场份额下降，意味着什么？增长被哪些渠道和公司捕获，哪些机制解释目前仍待验证？

首题选择原因：它可以在一个受控范围内同时训练 Baseline、NOP/APE、结构/趋势/比率、边际贡献、具名公司、逻辑链、证据分级和单页表达。

## 3. 双层产物

| 层级 | 产物 | 用途 |
|---|---|---|
| 分析实例层 | 问题卡、分析合同、证据表、逻辑链、单页 | 回答这次 HKIA 业务问题 |
| Agent 协议层 | 状态机、输入输出 Schema、阶段门、异常清单、人工 Gate | 让未来相似分析可重复运行 |

## 4. 推进阶段

| 阶段 | 要回答的问题 | 核心产物 | 放行条件 |
|---|---|---|---|
| G0 项目定义 | 为什么做、交付给谁 | 本 README、执行记录 | 双层目标和首题清楚 |
| G1 问题合同 | 究竟比较什么 | 问题卡、分析合同 | 字段完整、无隐含口径 |
| G2 证据就绪 | 有什么事实能回答 | 数据清单、字段映射、质量报告 | 来源、公式、分母、断点可追溯 |
| G3 分析成立 | 数字支持什么判断 | 三镜、边际、逻辑链、A/B/C | 事实可复算，机制有反证 |
| G4 页面可用 | 决策者能否独立读懂 | 一页分析 | 图文一一对应、公司具名 |
| G5 方法转正 | 哪些动作值得固化 | Agent 协议、复盘 | 同类动作重复验证后再自动化 |

## 5. 目录说明

```text
01_定义/  决策问题、分析合同、范围与边界
02_证据/  数据移交、字段映射、证据登记、质量检查
03_分析/  三镜、边际分解、逻辑链、证据分级
04_交付/  单页故事板、图表和最终 Deck
05_复盘/  DoD、异常清单、方法论转正候选
```

## 7. 学习时应观察什么

每个阶段都记录四件事：

1. 这一步消除了哪一种不确定性；
2. 输入和输出如何被明确描述；
3. 哪些检查可以由规则完成；
4. 哪些判断必须由人负责。
