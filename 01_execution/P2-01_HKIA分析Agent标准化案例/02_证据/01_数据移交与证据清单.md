# G2-01 数据移交与证据清单

> 用途：这是从 G1 进入 G2 的唯一入口。先确认数据资产，不要求 Jasper 重新整理一套完美数据。

## 1. 最小数据移交包

请优先提供现有路径或文件，不必复制：

| 优先级 | 资产 | 最低要求 | 用途 |
|---|---|---|---|
| P0 | 市场年度总量事实表 | 2019—2025；NOP/APE 或可计算源字段 | 总量和市场分母 |
| P0 | 渠道年度事实表 | 年、渠道、金额；最好含 NOP/APE | 三镜和渠道贡献 |
| P0 | 指标/字段字典 | 字段名、单位、公式、对象范围 | 签核分析合同 |
| P0 | 数据生成脚本或查询 | 能追溯事实表如何形成 | 独立复算 |
| P1 | 公司 × 渠道单维事实 | 公司名、年、渠道金额/份额 | 具名公司落点 |
| P1 | 缴费/产品/货币事实表 | 单维或合法二维 | 平行机制证据 |
| P1 | 断点/对账审计 | 2024 前后两条市场链差异 | 控制监管断点 |
| P2 | 既有图表或 Deck | 可不含底稿 | 对照历史判断，不作为唯一事实源 |

## 2. 每张事实表登记字段

| 字段 | 说明 |
|---|---|
| asset_id | 稳定资产编号 |
| path_or_query | 文件路径、表名或查询 |
| owner | 维护人 |
| source | HKIA 原表或派生来源 |
| coverage | 时间、对象、公司范围 |
| grain | 每一行代表什么 |
| measures | 原始指标和派生指标 |
| unit | HK$、千、百万、十亿等 |
| refresh_date | 最近更新时间 |
| known_breaks | 断点、缺失和映射变化 |
| reproducible | 是否存在生成脚本 |

## 3. Agent 自动检查候选

- 必填字段是否存在；
- 年份是否覆盖 Baseline；
- 渠道分类是否互斥并可回加总；
- NOP、APE 是否与源字段公式一致；
- 份额分项是否约等于 100%；
- 渠道增量是否回加至市场总增量；
- 单位是否在跨表连接时发生千/百万错位；
- 2024 前后是否出现系统性断点；
- 公司别名是否一对多或跨期漂移；
- 图表中的数字是否能回溯到事实表行。

## 4. 必须保留的人工判断

- 对象范围是否真正对应业务问题；
- 渠道映射变化是否具有业务含义；
- Peer Set 是否合理；
- B 级机制是否有可信替代解释；
- 页面标题是否在证据强度内。

## 5. G2 放行标准

只有当 P0 资产全部定位、字段合同完成映射、关键公式可复算、断点被显式记录后，才进入 G3 正式分析。
