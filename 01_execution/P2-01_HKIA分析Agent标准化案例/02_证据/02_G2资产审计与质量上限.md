# G2-02 HKIA 资产审计与当前质量上限

## 1. 资产盘点结论

| 资产层 | 现状 | 对首题的价值 |
|---|---|---|
| 原始监管文件 | 2015Q1—2026Q1，共45份 `.xls/.xlsx` | 独立事实锚点 |
| 统一数据库 | `hkia.db`，59,516行，45期 | 可复算分析底座 |
| 逻辑事实类型 | 新造、有效、币种、渠道、缴费年期、公司、公司×渠道 | 支持三镜、边际和公司落点 |
| 解析与标准化 | 文件发现、双引擎解析、schema标记、SQLite写入 | 支持重复运行 |
| 分析技能 | 增长分析、公司排名、总保费/标准保费参数化 | 支持确定性派生 |
| 测试 | 9项集成测试及原表抽查 | 已有质量基础，但尚未覆盖每个分析结论 |
| 老板知识库/经验 | 未接入 | 无法继承行业机制、判断阈值和历史案例 |

数据库物理上只有统一表 `long_term_business`；所谓公司表、渠道表等是 `table_type` 逻辑类型。未来 Agent 不应假设每个逻辑事实类型都有独立物理表。

## 3. 当前能产出的分析质量

### 可以较高质量交付

- 时间、对象、口径、分母和断点清楚的事实页；
- NOP/APE、规模/份额、结构/趋势/边际并列分析；
- 互斥维度内可回加总的贡献分析；
- 公司或渠道的具名排名、金额和份额变化；
- 对数据空白、断点和禁止推断的明确说明。

### 可以提出，但必须标为机制假说

- 开放渠道是否更能承接大额、趸交或配置型需求；
- 渠道迁移与产品、货币、缴费结构是否方向一致；
- 某些公司的渠道结构是否增强了增量捕获能力。

### 当前不能高质量确定

- 客户选择某渠道的真实动机；
- 代理人数量、生产率、留存和活动率的因果影响；
- 公司渠道激励、销售流程与产品策略的真实动作；
- 增长对应的利润、EV、资本占用和持续率结果；
- 老板基于历史经验形成的异常阈值、Peer选择和机制优先级。

## 4. 质量上限判断

在不接老板知识库、只使用行业数据和公开信息的条件下，当前最合理的上限是：

> **高质量事实诊断 + 有证据约束的机制假说 + 清晰的数据升级清单。**

它可以成为可信的分析底稿或讨论材料，但还不能等同于深度经营洞察。真正的差距不在图表，而在三个位置：

1. 机制优先级：哪些原因最值得先验证；
2. 商业意义：变化对渠道经营和公司能力意味着什么；
3. 行动映射：结论应触发什么决策或验证动作。

## 5. 本轮暴露的 Agent 检查项

- 百分比底层值是 `0.34` 还是 `34`，展示层必须自动识别或显式声明；
- 新旧 schema 的字段名和分类变化不能仅靠相似文本合并；
- “整付保费”需排除保单数与承保保额字段；
- 逻辑事实类型不能被误认作数据库物理表；
- 每条标题必须同时保存公式、分母、期间和证据等级。
