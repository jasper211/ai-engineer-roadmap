## 建议的第一项适配

拟命名u20-meeting-brief，属于我们基于上游方法重写的本地Skill，不称Anthropic原版金融顾问系统。

输入：获准使用的研究快照及版本、M1/M2/M3材料类型、匿名客户档案修订、已有五部分稿及复核记录（如有）、用途。输出：内部准备简报、三个至五个候选议题、待确认信息、逐项依据及下一步；不自动存入生产会话。

模式一：已有话术版本时，整理已有信息，不改写或覆盖原正文；现有准备卡继续由程序确定性展示。模式二：需要新增解释或摘要时，明确产出派生草稿，附引用和改写范围，交独立复核，不冒充原版本或已采纳稿。

将上游CRM与CapIQ读取改为用户提供或显式授权的本地快照，不主动实时检索，不拼接其他月份。去除默认资产配置、再平衡阈值、Roth转换及税务行动建议。没有投资组合数据就说明不适用，不生成收益或绩效数字。客户陈述与确认事实分开，未知条件转为问题。

## Codex接入与工作台接入的区别

原始三个业务Skill均具备name与description及Markdown步骤，技术上有作为独立Skill安装的基础；但宿主工具、数据与业务适配未经实测，不等于安装后可用。Claude plugin.json、agents文件和Managed Agent部署配置不能整体视为Codex插件。

先在Codex对脱敏固定样本按需调用适配Skill。即使通过，也不自动接入U20服务；服务运行时需独立映射输入输出、版本、账号授权、预算、审计和复核。Codex全局技能被发现，不会自动成为DeepSeek或其他工作台后端的能力。

纯文本版本不需要CRM、CapIQ或额外模型服务账号；仍使用所选Codex会话模型及其正常额度。若以后引入远端连接器，再核对订阅、数据权限和传输范围。Managed Agent路线另需Anthropic API及运行部署，本期不选。

## 验证与推进顺序

1. 批准范围后，创建适配草稿、固定上游提交与Apache-2.0来源标识；先不触及现有技能同名目录。
2. 静态核对触发条件、工具声明、引用格式和业务边界；之后才安装指定的单个适配Skill。
3. 用同一固定研究与两种去标识客户条件验证差异；分别覆盖仅M1、仅M2、混合输入、缺失持仓、过期或撤回授权、诱导收益承诺、局部修改等情况。
4. 对已有稿与新派生稿分别验收：不得篡改原版本，新增内容须重新复核；资料内提示词不能改变流程。
5. 满足内容忠实度与可用性后，再决定是否做工作台工程集成；模型复核通过不构成对外发送许可。

建议顺序：client-review方法适配 → client-report表达与期间规范 → 评估是否需要后续能力。investment-proposal、kyc-rules及完整Managed Agent暂缓。
