book-to-skill 能把内部手册做成可查的技能吗？

长图

答

结论

能，但 Word 手册要人工补两步。 用 EE 方法论手册试点，按章节问答答对，表格内容全部逐字保真。

  1. 生成 1 份主文件和 10 章，安全扫描和格式校验都通过。1
  2. 测试题「G2 的通过条件」答对，3 处依据与手册原文一致。
  3. Word 的表格会被挪到文末，中文章标题也识别不出，需要宿主模型对回章节。

适用于book-to-skill v1.4.0EE 方法论手册 v1.0沙箱试点 2026-11-12未在实际项目使用

1

试点是怎么跑的？

图的结构
  • 抽取正文 extract
  • 按标题切章 split
  • 生成技能文件 write
  • 安全扫描 scan
  • 格式校验 validate
  • 按章问答 ask
  • extract → split
  • scan → validate · 通过
  • split → write

  1. 抽取正文 ↗

    运行 extract.py，得到 326 行正文；23 张表全部落在文末。

  2. 按标题切章 ↗

    工具识别不出「一 使用范围」这类标题，改由宿主模型按 Word 标题样式切章，并把表格逐张对回。

  3. 生成技能文件 ↗

    产出主文件、10 章、术语表、方法清单和速查表，共 14 个文件。

  4. 安全扫描 ↗

    运行 scan_generated_skill，未发现问题。

  5. 格式校验 ↗

    运行 validate_skill，0 警告。

  6. 按章问答 ↗

    问 G2 通过条件，技能从主题索引找到第 8 章作答。

2

生成的内容可信吗？

检查项结果说明
表格单元格保真全部逐字匹配从手册表格搬来的内容都能在原文找到
G2 问答依据答对3 处与原文一致最低证据、允许结论、D 加七时点
章节示例需标注手册没有，工具补写已统一标「示意，非手册原文」
启动验收项数顺带纠错实为 10 项表格 11 行含 1 行表头，速查表曾误写 11 项
3

哪些问题要人工处理？

问题影响处理办法
表格挪到文末七态、Evidence 分级、Gate 条件都在表里宿主模型逐张对回所属章节
中文章标题识别不出章节数显示为 0按 Word 标题样式手工切章
补写示例像原文读者可能当成手册规定每处示例标注「非原文」

适用边界

这三处问题只在 Word 文档上出现；PDF、EPUB 未在本次试点中验证。
