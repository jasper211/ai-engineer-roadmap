# 方法清单

## 项目开始的五项证据
**When to use**：判断项目是否真的开始，或被告知「已启动」时。
**How**：逐项核对唯一入口、章程和范围、实名责任和 Readback、执行主账和阶段门、证据索引和关闭规则。
**Trade-offs**：检查快，但只是浓缩版；正式判断用启动验收 10 项（Ch 10）。

## 启动十个工作日（D 减三至 D 加十）
**When to use**：新项目从意向进入执行。
**How**：D 零发出章程与任务书 → D 加一 Readback → D 加二 RACI → D 加三基线和主账 → D 加五 G1 → D 加七 G2 → D 加十审查后进入周度运行（Ch 3）。
**Trade-offs**：复杂项目可延长，但不得跳过责任签收和事实基线。

## 事实变更流程（六步）
**When to use**：任何事实状态要改变时。
**How**：提交事实和证据 → 登记 Fact ID 与新旧状态 → 专业 Owner 确认专业事实、Principal 确认影响 → 更新基线或 Decision → 同步主账、Dashboard、周报、Case → 旧版本进 Archive（Ch 5）。
**Trade-offs**：比口头更新慢，但能防止多文件各自改写。

## 任务书九段主线
**When to use**：恢复、跨团队协作或存在争议的任务。
**How**：现状 → 事实差距 → 问题 → 根因 → 解决方案 → 交付物 → 预期结果 → 验收标准 → 时间和升级（Ch 6）。
**Trade-offs**：普通任务用 11 个最低字段就够，不必每项写九段。

## Readback 六问
**When to use**：任务发出后一个工作日内。
**How**：接受与否、首个交付物、承诺日期、实际执行人、依赖与调整、不接受时的替代方案（Ch 6）。
**Trade-offs**：增加一次往返，换来明确承诺；沉默不视为接受。

## 完成和关闭的验收链（六步）
**When to use**：任何任务要标 DONE 或 CLOSED 时。
**How**：提交交付并说明范围 → 登记 Evidence → 验收人接受、返工或拒绝 → 专业 Owner 复核 → 主账与 RAID 同步 → Dashboard 与周报一致（Ch 7）。
**Trade-offs**：不允许批量改状态。

## Gate Review
**When to use**：阶段点，按 G0 到 G5。
**How**：核对进入条件和最低证据 → 只用该 Gate 的允许结论 → 写附带条件和 Due → 批准人签 → 回写主账（Ch 8）。
**Trade-offs**：硬边界事项必须另设专业 Gate。

## 恢复七步法
**When to use**：大量逾期、Owner 不清、状态矛盾或 Dashboard 失真时。
**How**：冻结扩张 → 恢复基线 → 逐项 Disposition → 实名 Readback → 恢复关键路径 → 完成证据关闭 → 账板对账（Ch 9）。
**Trade-offs**：短期停止新增任务；不能用批量顺延 Due 代替。

## 周五锁账
**When to use**：每周五。
**How**：锁定主账 → 同步 Dashboard → 导出 JSON 或 PDF 快照并生成文件清单或 hash → 下周新版本，旧版本进 Archive（Ch 7, Ch 9）。
**Trade-offs**：要求周内严格回写。
