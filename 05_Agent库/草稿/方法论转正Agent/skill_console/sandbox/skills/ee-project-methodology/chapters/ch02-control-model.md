# 第 2 章：六层项目控制模型，Project 层与 Case 层
（对应手册：第二节、第三节）

## Core Idea
项目按六层建立控制，每层解决不同问题、有自己的最小交付物和通过条件；同时要两条线并行：Project 层建能力，Case 层用一个真实对象验证能力。

## Frameworks Introduced
- **六层项目控制模型**：
  | 层级 | 要解决的问题 | 最小交付物 | 通过条件 |
  |---|---|---|---|
  | 方向层 | 为什么做，做到什么程度 | 项目章程、Scope Spec、成功标准 | Owner 确认目标、边界、周期和决策点 |
  | 事实层 | 哪些已确认，哪些待核验 | 共同事实基线、Change Log、Decision Log | 事实有状态、Owner、来源和证据 |
  | 责任层 | 谁负责、执行、验收 | RACI、角色任务书、Readback | 自然人接受任务并给出日期 |
  | 执行层 | 当前做什么，如何推进 | Master Plan、Action、RAID、Case Register | 任务有交付物、依赖、Due 和下一动作 |
  | 验收层 | 凭什么算完成 | Evidence Index、验收记录、Gate 记录 | 交付、证据、验收和状态回写齐全 |
  | 汇报恢复层 | 管理层看到什么，偏差如何纠正 | Dashboard、周报、恢复任务书 | 账板一致，逾期有 Disposition 和新承诺 |
  - 规则：不能用 Dashboard 替代主账，也不能用主账里的一行状态替代真实交付物。
- **Project 层 ÷ Case 层**：
  | 比较项 | Project 层 | Case 层 |
  |---|---|---|
  | 控制对象 | 项目整体和各工作流 | 单个真实客户、需求、业务对象或交付 |
  | 主要问题 | 能力和机制是否准备好 | 能否完成一次可验收结果 |
  | 核心记录 | 章程、计划、Action、RAID、Decision | Case ID、对象、授权、阶段、结果、证据 |
  | 完成口径 | 阶段目标通过 Gate | 成功、失败或终止均有对象确认和证据 |
  | 相互作用 | 为 Case 提供主体、资源、标准和边界 | 向 Project 反馈真实效果、失败原因和改进 |

## Key Concepts
- **Case**：一个真实业务对象的完整交付记录。收到线索、简历、需求方向或演示数据，都不足以单独构成有效 Case。
- **文件建设**：只有 Project 层没有真实 Case 时的失败形态。
- **个人临时协调**：只有 Case 层没有 Project 控制时的失败形态。

## Mental Models
- 用六层表做诊断：哪一层的「通过条件」不满足，就从哪一层补。
- 把 Case 当作 Project 能力的「试金石」：失败的 Case 也是有效结果，只要有对象确认和证据。

## Anti-patterns
- **Dashboard 代替主账**：汇报视图不是事实源。
- **主账一行状态代替交付物**：状态不是证据。
- **把线索或演示数据当 Case**。

## Key Takeaways
1. 六层各有最小交付物，缺一层就缺一类控制。
2. Project 与 Case 必须并行。
3. Case 的完成口径包括失败和终止，关键是有确认和证据。
