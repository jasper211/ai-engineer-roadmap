# 第 1 章：使用范围、负责人职责与项目开始的五项证据
（对应手册：卷首核心结论、「项目开始的五项证据」、第一节）

## Core Idea
建群、开会、发任务、建文件夹都不等于项目已经启动。只有范围、共同事实、责任人、执行主账、验收证据和阶段门**同时**建立，项目才进入受控执行。

## Frameworks Introduced
- **项目开始的五项证据**：判断「项目是否真的开始」的五个检查点。
  - 用在：项目自称「已启动」时，先逐项核对。
  - 怎么查（每项负责人都要能答出对应的问题）：
    1. 唯一工作区和当前入口：团队从哪里读取同一份事实和当前版本？
    2. 经确认的章程和范围：项目解决什么问题，何时结束，哪些事项不做？
    3. 实名责任和 Readback：谁承担结果，谁执行，谁验收，谁作专业判断？
    4. 执行主账和阶段门：当前有哪些任务、Case、风险、依赖和下一次决策？
    5. 证据索引和关闭规则：一项任务凭什么完成，谁签收，状态是否已回写？
- **负责人必须先确认的五件事**：
  1. 目标和结束决策：到哪个节点决定继续、调整、扩张或停止；
  2. 范围和边界：区分当前必达、未来范围、建议方案、待核验事实和明确不做；
  3. 授权和资源：任命 Principal、Case Manager 或 PM、工作流负责人、专业确认人、验收人；
  4. 第一批真实对象：至少一个真实客户、业务主体、产品、流程、数据集或交付 Case；
  5. 验收口径：交付物、证据、接受人、阶段门、未达标时的处理方式。

## Key Concepts
- **适用范围**：联合项目、产品建设、经营验证、组织改造、数据和合规建设等跨团队协同工作。
- **不替代的东西**：业务方案、法律意见、财务审批、专业技术设计。
- **可调与不可调**：控制结构保留；工作流、字段和阶段门按风险、周期、交付对象调整。

## Mental Models
- 把「项目已启动」看成一个需要五项证据支持的**结论**，而不是一个动作。
- 用「第一批真实对象」防止项目长期停在框架层。

## Anti-patterns
- **替业务负责人编造**客户需求、经营目标、工作量或产能。
- **替专业负责人下结论**：财务、法务、合规、牌照、数据。
- **以口头认可代替** Readback、签收或正式 Decision。
- **为赶日期跳过**证据、授权、真实数据或合规阶段门。

## Worked Example（示意，非手册原文）
> 手册本身没有示例。以下场景为说明规则用的虚构示意，规则依据见本章上文。

用五项证据检查一个「已经建群开会两周」的项目：
| 证据 | 现状 | 结论 |
|---|---|---|
| 唯一入口 | 资料散在三个群和两个网盘 | 未建立 |
| 章程和范围 | 有方案 PPT，未写「不做事项」 | 未确认 |
| 实名责任 | 任务发在群里，无 Readback | 未建立 |
| 主账和阶段门 | 无主账，无 Gate | 未建立 |
| 证据索引 | 无 | 未建立 |
→ 按第 10 章启动验收标准，项目只能标为「启动中」，不能对外说「已正常运行」。

## Key Takeaways
1. 启动是一个需要证据的结论。
2. 先确认目标和停止条件，再谈工作流。
3. 至少指定一个真实对象，否则项目会变成文件建设。
4. 负责人的边界：组织和控制，不代替业务与专业判断。
