# 第 4 章：角色和责任
（对应手册：第六节）

## Core Idea
每个角色都有「必须完成」「不得替代」「主要验收」三栏；「不得替代」与「必须完成」同等重要，是防止越权和代签的关键。

## Frameworks Introduced
- **角色责任表**：
  | 角色 | 必须完成 | 不得替代 | 主要验收 |
  |---|---|---|---|
  | 项目 Owner | 确认目标、边界、预算、标准和停止条件 | 不直接填充各专业事实 | 章程、范围和重大 Decision |
  | Project Principal | 整合交付、指定负责人、解决冲突、批准 Gate | 不替执行人交付，不替专业 Owner 判断 | 阶段结果、资源和优先级 |
  | Case Manager 或 PM | 维护共同事实、主账、RAID、Evidence、周报和升级 | 不编造业务、预算、法律或技术结论 | 字段完整、状态一致、证据可追溯 |
  | 工作流负责人 | 按任务书产出专业交付并说明依赖 | 不以会议参与代替交付 | 工作包和阶段出口 |
  | 专业 Owner | 对法律、财务、数据、牌照、安全等给出书面结论 | 不由项目管理角色代签 | 版本、适用范围和批准记录 |
  | Case Owner | 推动单个真实对象达到成功、失败或终止结论 | 不以中间动作冒充结果 | 对象确认、结果和复盘证据 |
  | SteerCo | 作战略、预算、重大风险和继续停止决策 | 不介入日常微任务 | 正式 Decision 和资源授权 |

## Key Concepts
- **Principal**：项目层的整合者与 Gate 批准人。
- **Case Manager 或 PM**：事实与主账的维护者，不是业务或专业的决定者。
- **SteerCo**：双周级的战略与资源决策机构。

## Mental Models
- 先问「这件事谁有权签」，再问「谁来做」。
- 项目管理角色的价值在于控制和追溯，而不是代替判断。

## Anti-patterns
- **项目管理角色代签专业意见**。
- **以会议出席代替交付**。
- **以中间动作冒充 Case 结果**。
- **SteerCo 介入日常微任务**。

## Key Takeaways
1. 七个角色，各有不可越过的边界。
2. Gate 由 Principal 批准；专业结论只能由专业 Owner 书面给出。
3. Case Owner 对单个真实对象的最终结论负责。
