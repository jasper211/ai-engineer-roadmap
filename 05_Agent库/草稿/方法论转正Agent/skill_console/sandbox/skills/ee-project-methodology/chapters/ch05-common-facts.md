# 第 5 章：共同事实控制
（对应手册：第七节「事实状态」「事实优先级」「事实变更流程」）

## Core Idea
共同事实不是一个大文件，而是一套**状态 + 优先级 + 更新纪律**：静态基线定义可共同使用的事实，执行主账记录动态状态，Dashboard 只呈现管理视图；三者冲突时先查批准状态和证据，再通过 Change Log 或 Decision 修正。

## Frameworks Introduced
- **事实七态**：
  | 状态 | 含义 | 可否作为已完成事实 |
  |---|---|---|
  | CONFIRMED | 已由有权 Owner 确认并进入当前基线 | 可以（仍受证据和授权范围限制） |
  | PRINCIPLE AGREED | 原则已同意，执行数字或文件未完成 | 不可以 |
  | TASK TO VERIFY | 需要指定责任人核验 | 不可以 |
  | PROPOSED | 待批准建议 | 不可以 |
  | TARGET STATE | 目标状态已确认，落地尚未完成 | 不可以 |
  | FUTURE SCOPE | 当前周期之外的候选工作 | 不进入当前必达 |
  | PLACEHOLDER | 为建账预留的对象 | 不计入经营或交付成果 |
- **事实优先级（从高到低）**：
  1. 已经批准且有证据的共同事实基线；
  2. 正式 Decision 和签署文件；
  3. 执行主账中的当前状态；
  4. Dashboard 和周报中的汇报视图；
  5. 会议纪要、即时消息、邮件和口头输入。
  - 低优先级输入与高优先级事实冲突时，Case Manager 登记冲突、Owner、影响和建议处理，**不能直接覆盖**。
- **事实变更流程六步**：
  1. 提交变化事实和证据；
  2. 登记 Fact ID、旧状态、新状态、影响对象和提出人；
  3. 专业 Owner 确认专业事实，Principal 确认项目影响；
  4. 更新共同事实基线或 Decision；
  5. 同步主账、Dashboard、周报和相关 Case；
  6. 被替代版本移入 Archive 并保留追溯。

## Key Concepts
- **共同事实基线**：已批准且有证据的事实集合。
- **Change Log / Decision Log**：事实变更与决策的追溯记录。
- **Fact ID**：事实条目的唯一标识。

## Mental Models
- 只有 CONFIRMED 算完成事实；其余六态都是「还在路上」。
- 冲突时按优先级裁决，不按谁说得最近。

## Anti-patterns
- **TARGET STATE 写成已完成**（第 10 章 LinkedOut 经验之一）。
- **在不同文件里各自改写同一事实**。
- **用聊天记录覆盖基线**。

## Worked Example（示意，非手册原文）
> 手册本身没有示例。以下场景为说明规则用的虚构示意，规则依据见本章上文。

会议上合作方说「数据接口已经开通」：
- 优先级：会议口头输入，第 5 级；
- 状态：最多记为 TASK TO VERIFY，指定核验人；
- 走变更流程：拿到接口文档或测试记录（证据），专业 Owner 确认后才能改为 CONFIRMED，并同步主账与 Dashboard。

## Key Takeaways
1. 七态中只有 CONFIRMED 可作为已完成事实。
2. 五级优先级决定冲突时听谁的。
3. 改事实要走六步，旧版本进 Archive。
