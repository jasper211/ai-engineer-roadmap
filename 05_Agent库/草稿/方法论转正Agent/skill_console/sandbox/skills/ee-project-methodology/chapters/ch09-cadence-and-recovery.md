# 第 9 章：周度运行节奏、逾期和项目恢复
（对应手册：第十三节、第十四节、第十五节首月行动表）

## Core Idea
运行靠固定节奏：每日回写、周二沟通、周四查逾期、周五锁账、双周 SteerCo、阶段点 Gate Review。项目失控时先停扩张、恢复共同事实和交付闭环——恢复不是把所有 Due 往后挪。

## Frameworks Introduced
- **周度运行节奏**：
  | 频率 | 固定动作 | 必须输出 |
  |---|---|---|
  | 每日 | 回写事实变化、Action、Case、RAG、下一动作和 Evidence | 主账 Updated At 可追踪 |
  | 周二 | 工作流和 Case 沟通，只处理状态变化、阻塞和决策 | Action、Decision、Owner、Due 和依赖 |
  | 周四 | 检查逾期、红灯、Evidence 缺口和本周承诺 | 恢复动作和升级清单 |
  | 周五 | 锁定主账，更新 Dashboard 和周报，对账 | 周快照、账板一致和下周重点 |
  | 双周 | SteerCo 审查范围、资源、预算和重大风险 | 正式 Decision |
  | 阶段点 | Gate Review | GO、CONDITIONAL GO、HOLD 或 STOP |
- **会议控制规则**：会前从主账生成议题；会上只形成事实确认、Decision、Action、Evidence 请求四类结果；会后限时回写 Owner、Due、依赖、结论和证据位置；需专业确认的标记待复核；周报只报变化、结果、风险、决策请求和下一步。
- **状态、优先级、RAG 三分**：状态描述执行阶段（不表达健康度）；优先级 P0/P1/P2 表达对关键路径的重要性（不等于紧急）；RAG（GREEN/AMBER/RED）表达健康与风险（GREEN 不等于完成）。
- **恢复七步法**：冻结扩张 → 建立恢复基线 → 逐项 Disposition（已完成待证据、阶段成果待拆分、重新激活、合并关闭、移出范围、待 Owner、决策升级）→ 实名 Readback → 恢复关键路径（P0、红灯、专业 Gate、第一批真实 Case）→ 完成证据关闭 → 账板对账，由 Principal 确认恢复。
- **可以宣布恢复正常的八条标准**：范围（当前必达与未来范围分开）、责任（P0 与红灯有自然人 Owner 并已 Readback）、到期任务（每项有 Disposition、新 Due、依赖和证据要求）、关闭（DONE 与 CLOSED 都有交付、Evidence、验收）、风险（红灯有 Decision Maker、方案和时限）、真实对象（至少一个真实 Case 受控推进）、账板一致、节奏（连续两个周期按时回写和验收）。
- **首月行动表**：启动周 → G0 和 G1；第一周 → G2 执行准备；第二周 → G3 交付形成；第三周 → G4 真实验证；第四周 → G5 或下一阶段授权。
- **负责人每周七问**：可验收结果、事实变化与证据、真实 Case 进度、阻塞的 P0/红灯/专业 Gate、未 Readback 与逾期、需要我作的 Decision、账板是否同版。

## Key Concepts
- **Disposition**：对每项旧任务的处置结论。
- **账板一致**：主账、Dashboard、周报、事实基线使用同一状态。

## Mental Models
- 逾期是信号，不是要调的数字；先 Disposition，再给新 Due。
- 周五锁账是一周的「结账日」。

## Anti-patterns
- **批量顺延 Due**。
- **会议从聊天记录拼议题**。
- **绿灯被当成完成**。

## Key Takeaways
1. 六个频率的固定动作和输出。
2. 恢复七步法，以及八条恢复标准。
3. 首月按周推进 G0 到 G5。
