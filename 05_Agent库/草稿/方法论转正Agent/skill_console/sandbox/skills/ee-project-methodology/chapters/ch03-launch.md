# 第 3 章：启动前准备与启动十个工作日
（对应手册：第四节、第五节、「启动完成的判断」）

## Core Idea
启动有固定顺序：先扫描材料、分层事实、定唯一工作区、确认角色、选真实对象；再按 D 减三到 D 加十的节奏完成认领、基线、首批拆解和首个 Gate。D 加十不自动代表正常。

## Frameworks Introduced
- **启动前准备五步**：
  1. 扫描现有材料：合同、会议记录、方案、系统、数据、历史交付、已有决策，标记来源与日期；
  2. 建立事实分层：已确认事实、原则共识、建议、假设、待核验任务、目标状态、未来范围、占位对象分开；
  3. 确定唯一工作区：正式入口、主账、Readback、会议记录、证据、历史版本放在同一受控目录；
  4. 确认角色和授权：先 Owner、Principal、Case Manager 或 PM，再工作流和执行人；
  5. 选择第一批真实对象：决策人可达、需求真实、证据可得、结果可观察、风险可控。
- **启动十个工作日**（通用默认节奏）：
  | 时间 | 负责人 | 必须完成 | 阶段出口 |
  |---|---|---|---|
  | D 减三至 D 减一 | Owner 和 Principal | 资料扫描、目标、边界、风险和候选工作流 | 启动输入清单 |
  | D 零 | Owner | 发布章程、Scope Spec、角色任务书和唯一入口 | 正式发出待认领 |
  | D 加一 | 全部责任人 | 提交 Readback：接受、调整或拒绝 | 责任认领完成 |
  | D 加二 | Principal | 补齐自然人 Owner、专业确认人、资源和升级路径 | RACI 生效 |
  | D 加三 | Case Manager | 共同事实基线、主账、RAID、Evidence Index 上线 | 事实和执行入口形成 |
  | D 加五 | 工作流负责人 | 完成首批工作包拆解和交付排期 | G1 基线 Gate |
  | D 加七 | Case Owner | 建立第一批真实 Case 或验证对象 | G2 执行准备 Gate |
  | D 加十 | Principal | 审查首批交付、证据、风险和资源 | 进入正常周度运行 |
  - 复杂项目可以延长，但不得跳过责任签收和事实基线。日期变更要在 Readback 或 Decision 中一次写明，不得只口头延期。
- **启动完成的判断**：同时满足才可从「启动中」改为「正常运行」：入口可读、范围已确认、责任人已 Readback、主账反映真实状态、首个 Gate 通过、第一批真实对象已建立。

## Key Concepts
- **D 零**：章程等正式发出、进入待认领的那一天。
- **启动输入清单**：D 零之前的出口物。

## Mental Models
- 把十个工作日看成「出口驱动」：每天看出口物有没有，而不是看日期到没到。

## Anti-patterns
- **口头延期**。
- **D 加十即宣布正常**。
- **先派执行人、后补 Owner**。

## Worked Example（示意，非手册原文）
> 手册本身没有示例。以下场景为说明规则用的虚构示意，规则依据见本章上文。

一个新项目的首周检查：D 加一时 6 名责任人中 2 人未 Readback → 按第 6 章规则，沉默不视为接受，Case Manager 记录、Principal 决定替代或调整；G1 推迟必须写进 Decision，而不是在群里说「晚两天」。

## Key Takeaways
1. 准备五步的顺序不能倒：先角色授权，再安排执行人。
2. 十日节奏中的 G1（D 加五）与 G2（D 加七）是关键出口。
3. 判断正常运行看六个条件，不看日历。
