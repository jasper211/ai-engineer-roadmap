## 七、基础设施Agent：Obsidian巡检Agent

### 7.1 定位

不属于业务产出层，是全部Agent+全部AI工具的公共支撑——确保Jasper使用的各AI工具在同一套准则下工作，尤其是知识库的调用和更新。

### 7.2 职责边界

- **AI工具集成与调配**：确保Claude/Kimi/Codex等不同AI工具调用知识库时遵循同一套规则
- **知识库更新与维护**：知识库本身的更新、同步、一致性检查归这个Agent管（**v1.4新增细化，见十二节**：包括vault内部文档描述的数字/状态是否跟实际数据一致，这类检查是巡检能力线的自然延伸）
- **与方法论转正Agent的边界**：方法论转正Agent管"Agent搭建方法论"这类流程规则+行业自学习线，Obsidian巡检Agent管"知识库内容本身+AI工具调用准则"；两者共用同一个vault但schema独立，融合机制见`双Agent协作契约_OB与方法论转正Agent.md`

### 7.3 现状（v1.4更新，取代v1.3记录的2026-07-18快照）

**v1.3记录的"本体化迁移已完成（6601/362原子）、图谱连通性43.2%→71.0%"是2026-07-18的快照，白名单收窄后这些具体数字已不适用**。截至2026-07-25的真实进展：

- **EA白名单从17项收窄到8项**：只保留"成型的方法论文档和结果文档"（项目章程/方法论标准/SOP/Agent执行机制梳理/规则空白地图/熔断节点补建清单/规则与GAP产出/信号提取基线），原子总量从万级降到千级，实时数字见vault内`MOC/仪表盘_项目全景.md`（不再在本文档写死具体数字，避免再次过期）
- **schema分类体系扩展**：新增`domain`字段（EA专属业务域）；`entity_type`新增7个白名单来源类分类（SOP/Agent机制/规则与GAP/方法论标准/规则空白/信号基线/熔断规则），解决此前87%原子`entity_type`是通用占位符的问题
- **历史遗留巨型枢纽已拆分**：白名单收窄前用无规模上限的旧脚本产出的3个巨型枢纽（财务流程与凭证36个原子/调度触发模式21个/绩效考核管理16个）已用LLM连贯性判断重新分组拆成14个更窄子枢纽，HUB_SIZE_CAP(15)超限枢纽数3→0；增量聚类（`cluster_atoms.py`）对新增原子的规模拦截本来就是对的，这次解决的是存量遗留问题
- **MCP多端接入**：`obsidian-mcp-server`已修复冷启动同步构建向量索引阻塞握手的bug；Claude Code已通过`claude mcp add --scope user`验证连接成功；Codex/Qoder配置已写入，待重启验证
- **DeepSeek模型切换**：从即将废弃的`deepseek-chat`别名切到显式`deepseek-v4-pro`

**仍然真实存在的技术空白——写入侧**：业务Agent（VNW/AIT/方法论）发现的新知识如何自动变成新的概念笔记写回vault，**目前仍完全没有对应的技术方案**。现有原子靠每日定时任务（`com.jasper.ob-daily-extract.plist`，**已激活**，非v1.3记录的"未激活"状态）批量增量提炼，不是任何业务Agent产出文件后触发的实时写入。

**读取侧同样存在真实差距**：OB的检索服务端已就绪，但PTA/VNW/AIT三个业务Agent里**仍然没有一行代码真正发起过这个调用**。

## 十二、文档一致性维护责任裁定（v1.4新增）

**背景**：2026-07-24复盘发现，OB/方法论转正Agent进展飞快，但描述它们状态的文档（本文档、OB/README.md、方法论转正Agent/README.md、vault内起点/MOC文档等）持续滞后，部分文档（如已废弃的《OBagent诊断与整合路线图_v1》）里的具体数字甚至和实际状态相差数倍，有实质误导风险。谁该负责保持这些文档同步，此前没有明确裁定。

**裁定**：按文档性质分两类，不设单一"文档维护Agent"：

1. **vault内部的数字/状态类文档**（如vault内`起点_从这里开始.md`、各类MOC诊断报告）——归**OB巡检能力线**。OB现有巡检本来就在做"声称状态vs实际状态"的核对（symlink完整性、MCP配置一致性、vault统计），"文档里的数字是否跟vault实际数据一致"是同一类检查的自然延伸，不是新增能力线。
2. **跨Agent的"进度快照"类文档**（本文档、`Agent搭建SOP.md`、`新项目设置草案`等描述多个Agent状态汇总的文档）——按六节定位，天然属于**方法论转正Agent的内部治理线**（"监测其余四个Agent的执行记录，回写进标准文档"），不该落到任何单个业务Agent头上（违反"主Agent不跨域"原则）。
3. **过渡期安排**：内部治理线尚未启动，第2类文档的同步工作**由AI协同终端在对话中人工代管**，直到内部治理线真正建成接手。这不是新增职责，是把此前一直在做但没有明确记录的事实写下来。
