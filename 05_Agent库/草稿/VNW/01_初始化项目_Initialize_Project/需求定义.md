# VNW 需求定义 v0.6.0

> 基线日期：2026-07-30  
> 当前阶段：第一阶段主体完成，正在进行合格 L3 的批量分析、质量验收与封版。

## 1. 产品目标

VNW 是“价值节点驱动的 L3 流程模型与 AI 重塑分析系统”。它把公司流程数据库、
正式流程蓝图、L4 复核材料和合格知识材料组织成可追溯的单 L3 事实快照，在统一
Gate、统一分析契约和统一前端下回答：

1. 该 L3 实际如何流转；
2. 产生哪些 L4 交付物；
3. 每个交付物由哪些任务构成；
4. AI 与人如何分工、哪些控制门不能越过；
5. 哪些任务值得优先开展 AI 试验；
6. 每一项展示和分析来自哪里。

## 2. 第一阶段范围

第一阶段实现：

- PostgreSQL `process_analytics` 只读事实接入；
- 流程蓝图、D1–D6 全量复核表、Skill 封装可行性表等补充源接入；
- 全量 L3 事实快照和稳定 Hash；
- Gate M/E/A 准入判断；
- 统一 L3 分析运行包、输出校验和安全发布；
- React 统一页面及 A/E/C/B/D/负责人决策/F 固定模块；
- 工作坊拖动结果浏览器本地保存；
- 数据库键、CSV/XLSX 行号、Markdown 行号等输入谱系。

第一阶段尚未完成的封版事项：

- 为全部符合条件的 L3 生成并抽检深度分析包；
- 固定跨业务域回归样本与验收阈值；
- 完成 01–11 工程说明书和发布版本基线。

## 3. 三阶段边界

| 阶段 | 目标 | 当前状态 |
|---|---|---|
| 第一阶段 | 统一输入、统一模型、统一展示，完成合格 L3 的可信分析 | 主体完成，封版中 |
| 第二阶段 | 源头变化检测、快照过期识别、系统与 Demo 更新 | 已实现V1手动触发闭环，待接入调度 |
| 第三阶段 | 工作坊交互治理、知识库写回和数据库精准变更协同 | 未启动 |

V1 不反向修改数据库或知识库。工作坊结论只保存在浏览器本地，不能冒充 SSOT。

## 4. 准入原则

- 缺少可解析流程蓝图、有效 L4、基本交付物或完整 D1–D6 时，不运行模型分析；
- 缺少规则或 SOP 时允许形成带缺口模型，但必须明确显示待完善项；
- Gate A 只判断能否进入 AIT 建设，不决定流程模型是否值得建立；
- 输入不足时宁可展示缺失，不使用行业常识或模板文字补造事实。

详细标准见
`03_规划项目结构_Plan_Project_Structure/L3流程模型准入标准_v0.1.md`。

## 5. 成功标准

- 所有 L3 使用相同输入优先级、Gate、分析契约和页面结构；
- 每条模型结论能够引用当前快照中的有效证据；
- 数据库事实、正式复核、材料补充、模型草稿和工作坊共识可区分；
- 源头变化后能够识别旧分析包过期，不静默沿用；
- 任务级建议落到可试验范围、人工边界和负责人待拍板事项；
- 不编造流程、岗位、量化收益、精确象限坐标或不存在的映射。

## 6. 非目标

- 代替数据库负责人修改权威库；
- 把 L2 整体能力描述为被 AI 替代；
- 将 L4 Tier 直接等同于任务级自动化结论；
- 将模型草稿直接当作业务确认结果；
- 在缺乏证据时批量生成看似完整的流程模型。
