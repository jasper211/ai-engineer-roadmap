# 11 监控与优化

本层监控 VNW 自身的数据、分析、展示和运行质量，不评价个人绩效。

## 1. 当前可检查指标

### 数据质量

- L3 总数和 Gate M/E/A 分布；
- 可解析蓝图覆盖率；
- L4 名称、交付物和 D1–D6 完整度；
- VN–L4、L3–L2 等桥接覆盖；
- 数据库事实与正式补充材料冲突数；
- 输入文件版本、Hash 和实际行号定位。

### 分析质量

- 已发布分析包数量；
- 当前、过期、缺失和校验失败状态；
- L4 分析覆盖率；
- 每个 L4 的任务覆盖和复合动作拆分情况；
- 未知或失效证据引用；
- 具体人名、无依据收益和伪造精确坐标等违规输出；
- COM、IRI、IBRD、HRA、HRM 回归样本一致性。

### 运行质量

- 快照构建、模型运行和前端构建成功率；
- 失败类型和最近成功时间；
- 单批 L4 刷新范围是否超过 6 个；
- 发布前是否生成备份和审计记录；
- 同一输入重复构建的 Hash 是否稳定。

## 2. 当前实现与缺口

当前监控主要依靠：

- `model_snapshots/index.json`；
- 各 L3 manifest；
- `analysis_runs/` 和 `analysis_packages/`；
- 自动化测试；
- 前端构建结果；
- 历史 `state.json`。

尚未建设集中监控面板、告警和自动重跑。这些属于第一阶段封版后的工程化工作，
不能因为缺少监控面板而把未校验分析发布为正式结果。

## 3. 优化闭环

```text
发现缺口 → 定位源对象/记录键/行号 → 判断是源数据、解析器还是模型问题
→ 在对应层修复 → 重建快照 → 回归测试 → 重新分析 → 人工抽检 → 发布
```

禁止直接在前端文案中掩盖源数据或分析问题。
