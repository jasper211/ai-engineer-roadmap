# 表级根因分析模型 v1.0

> 标准ID：`VNW-TABLE-ROOT-CAUSE-v1.0`
> 输入：全部业务数据表的精简血缘证据包(fact_pack，每张表含schema.table/中文名/表类型/行数/真实上下游/已确认L4及其交付物)
> 输出：`vnw.table-root-cause.v1` JSON
> 禁止：引用fact_pack以外的表名、L4、血缘关系；编造任务耗时、岗位、人力信息；输出CONFIRMED状态。

## 1. 分析原则

1. 每张表的`upstream`/`downstream`只能从该表fact_pack给出的列表里原样引用(用`key`匹配)，不能新增、合并、推测未出现的表；
2. `task_cluster.label`必须从下面第2节的6个固定枚举里选一个，不能自创新分类、不能输出枚举以外的文字；
3. `hidden_deliverables`里每条的`l4_code`只能是该表fact_pack.`related_l4s`里真实列出的编码，不能凭空发明新L4、不能借用其他表的L4；
4. 只有当这张表的中文名/表类型/血缘位置明显指向的加工内容，和该L4已记录的`deliverable`文本对不上、或`deliverable`本身语焉不详时，才输出候选；没有明显缺口的表`hidden_deliverables`输出空数组，不能为了"有产出"硬凑一条；
5. 全部标注`"status": "MODEL_DRAFT"`，不允许输出`"CONFIRMED"`；
6. `related_l4s`为空的表(尚未纳入L3分析范围)，`hidden_deliverables`必须留空，只做`task_cluster`聚类；
7. 判断依据只能是fact_pack给出的字段(`business_label`/`table_type`/`row_count`/`has_lineage`/`upstream`/`downstream`/`related_l4s`)，不得引入表结构以外的假设——不猜测具体列名、不猜测使用频率、不猜测负责人。

## 2. 任务特征聚类固定枚举

对每张表，结合它的血缘位置(`upstream`/`downstream`数量、`has_lineage`)和`table_type`，从下面6类里选一个最贴切的，并给出一句话理由(必须引用该表的具体上下游数量或表类型作为依据，不能只是复述定义)：

| 枚举值 | 判定依据 |
|---|---|
| 源头采集型 | 没有真实上游(`upstream`为空)但有下游，是数据进入本系统的起点——原始录入/批量导入类任务 |
| 枢纽整合型 | 上游和下游都比较多(各≥3条)，是被广泛引用的核心整合点——主数据维护/多方核对类任务，出错会向外扩散 |
| 终端消费型 | 只有上游、没有下游(`downstream`为空)，是数据链路的末端产出——报表/看板生成类任务 |
| 规则配置型 | `table_type`是配置表/规则表，连接度通常不高——规则/参数维护类任务，人工低频操作但影响面大 |
| 直通转换型 | 上下游各只有少量边(通常各1-2条)，处于链路中段——格式转换/清洗类任务 |
| 孤立支撑型 | `has_lineage`为false，没有真实血缘边——独立于可追踪主链路之外的人工维护/外部系统落地/纯参照类任务 |

## 3. 输出结构

```json
{
  "tables": [
    {
      "key": "schema.table",
      "layer3": {
        "status": "MODEL_DRAFT",
        "upstream": [{"key": "schema.table", "business_label": "...", "edge_type": "view_dependency|foreign_key|pipeline_sibling"}],
        "downstream": [{"key": "schema.table", "business_label": "...", "edge_type": "..."}],
        "task_cluster": {"label": "枢纽整合型", "rationale": "上游N条/下游M条，且table_type为..."}
      },
      "layer4": {
        "status": "MODEL_DRAFT",
        "hidden_deliverables": [
          {"l4_code": "L4-XXX-01", "l4_name": "...", "candidate_name": "候选过程产物的简短命名", "rationale": "为什么该L4已记录的deliverable文本没有覆盖这张表体现的加工内容"}
        ]
      }
    }
  ]
}
```

- `upstream`/`downstream`直接复制该表fact_pack里对应的条目（不要求全部照抄，但每一条都必须能在fact_pack里找到完全匹配的`key`）；
- 每张fact_pack里出现的表都必须在输出`tables`数组里有对应一条，不能遗漏；
- 输出必须是合法JSON，不要输出JSON以外的说明文字。
