# VNW流程模型系统三阶段实施路线 v1.0

> 冻结日期：2026-07-29  
> 核心约束：数据库始终只读；事实、模型分析、工作坊共识不得混层；缺失不得编造。  
> 当前执行阶段：第一阶段。

## 1. 第一阶段：统一Demo与流程模型系统

### 1.1 目标

所有L3追溯同一输入源，使用同一分析标准和同一展示逻辑。COM是金标准样本，
但不保留永久专用渲染分支。

### 1.2 固定输入

- 数据库：`process_analytics`只读事实；
- 流程知识：L3流程蓝图；
- 补充知识：只读取状态为生效的正式知识；
- 正式复核：L4两阶段复核等已确认结构化材料；
- 工作坊内容：只作为浏览器本地共识，不进入事实包。

### 1.3 固定分析标准

- 分析标准ID：`VNW-L3-COM-GOLD-v1.0`；
- 分析包Schema：`vnw.l3-analysis.v1`；
- 所有模型结论必须引用当前L3事实包中的`evidence_id`；
- 没有证据时输出缺失态；
- 模型输出统一标记为草稿，不能冒充数据库判断或业务确认。

### 1.4 固定展示顺序

1. 页首摘要与Gate；
2. 面板A：流程蓝图；
3. 面板E：L4交付物地图；
4. 面板C：任务卡片墙；
5. 面板B：人机协作与控制地图；
6. 面板D：AI机会优先级；
7. 负责人决策；
8. 面板F：SSOT与证据。

所有L3均保留全部面板。输入不足时显示统一缺失态，不隐藏面板、不改变顺序。

### 1.5 验收条件

- 67/67个L3使用同一事实快照生成器；
- 67/67个L3使用同一分析契约；
- COM、IRI、IBRD使用同一React组件，无专用HTML业务逻辑；
- 三个回归样本逐面板字段和交互一致；
- 模型分析、数据库事实、正式补充和工作坊共识视觉可区分；
- 任意分析可定位到证据ID和源对象；
- 前端生产构建和自动测试通过。

## 2. 第二阶段：源头更新驱动系统与Demo更新

### 2.1 目标

数据库或知识源变化后，自动识别受影响的L3、L4、任务和分析结论，增量更新系统，
不静默覆盖已确认共识。

### 2.2 核心能力

- 数据库查询结果Hash；
- 知识文件Hash与版本；
- 新旧事实快照差异；
- 字段级影响分析；
- 受影响模块增量重建；
- 旧模型分析失效提示；
- 工作坊草稿基线过期提示；
- 更新审计记录与失败恢复。

### 2.3 阶段边界

本阶段只更新只读系统和Demo，不实现知识库或数据库回写。

## 3. 第三阶段：交互与回写闭环

### 3.1 目标

将工作坊交互从浏览器临时状态升级为受控变更流程，同时保持数据库只读。

### 3.2 核心能力

- 工作坊会话保存；
- 负责人确认；
- 结构化变更提案；
- 知识库待复核区；
- 人工审核后转为定稿知识；
- 数据库修改工单；
- 精准定位Schema、表、业务键、字段和当前值；
- 数据库负责人修改后的只读验证；
- 知识、数据库和系统模型重新对齐。

### 3.3 禁止事项

- 前端交互不得直接修改数据库；
- 模型建议不得自动进入正式知识；
- 卡片拖动不得自动改变Gate；
- 数据库与知识冲突不得静默覆盖。
