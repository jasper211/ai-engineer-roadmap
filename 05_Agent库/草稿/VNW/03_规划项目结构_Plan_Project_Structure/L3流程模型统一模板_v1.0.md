# L3 流程模型统一模板 v1.0

> 日期：2026-07-29  
> 状态：冻结为 IRI、IBRD、COM 三个 Demo 的统一重构基线  
> 适用范围：单个 L3 的独立 HTML Demo；后续可直接映射到 React 组件  
> 核心原则：结构固定、内容自适应；缺失即声明缺失，不编造补齐。

## 1. 模板目标

同一套模板必须同时回答六个问题：

1. 这个 L3 实际如何流转；
2. 哪些环节必须由人负责或复核；
3. 每个 L4 交付物适合怎样的人机分工；
4. 哪些 L4 值得优先讨论，依据是否充分；
5. AI 重塑了哪些交付物的生产逻辑；
6. 负责人本轮需要作出什么决定。

不同 L3 只允许改变业务内容、数据数量和缺失状态，不允许改变面板语义、证据语言和交互规则。

## 2. 固定页面结构

页面顺序固定如下，任何样本不得重排：

| 顺序 | 模块 | 固定用途 | 是否允许隐藏 |
|---|---|---|---|
| 0 | 页首摘要 | L3定义、Gate、完整度、证据快照 | 否 |
| A | 流程蓝图 | 展示真实步骤、顺序、箭头、决策点、回退线 | 否 |
| B | 人工控制与协作 | 展示责任、核心介入点、强制关卡和异常责任 | 否 |
| C | AI任务工作坊 | 按 Human/Hybrid/Aug/Auto 拖动 L4 任务卡 | 否 |
| D | AI机会优先级 | 四象限工作坊，区分数据判断与共识假设 | 否 |
| E | L4交付物地图 | L3目标—L4交付物—具体能力—价值节点 | 否 |
| F | SSOT与证据 | 原始字段、来源、冲突、缺失和版本 | 否，可折叠 |
| 结论 | 负责人决策 | 仅输出与当前 L3 相关的通俗决策项 | 否 |

“不允许隐藏”不代表必须生成内容。缺少输入时保留面板并显示统一缺失态。

## 3. 四层证据视觉

所有展示内容必须属于以下一层：

| 层 | 含义 | 默认视觉 | 使用规则 |
|---|---|---|---|
| 数据库事实 | PostgreSQL 当前原值 | 蓝色 | 不被其他来源静默覆盖 |
| 正式复核 | 368条两阶段复核表等已形成的逐L4评估 | 绿色 | 可作为工作坊初始建议，必须并列保留数据库原值 |
| 材料补充 | 生效蓝图、正式SOP、OB定稿知识 | 黄色或紫色 | 显示文件、版本、状态、置信度 |
| 工作坊共识 | 拖动、调整、负责人确认 | 橙色 | 只保存在浏览器，不冒充SSOT |

缺失、冲突、待复核分别使用：

- `MISSING`：灰色；
- `CONFLICT`：红色；
- `UNVERIFIED`：虚线黄色；
- `CONSENSUS`：橙框。

## 4. 固定数据优先级

### 4.1 事实字段

编码、名称、数据库交付物、数据库 Tier、桥接关系等事实字段遵循：

```text
PostgreSQL权威库 > 正式源文件 > 生效蓝图/SOP > OB定稿知识
```

低优先级来源不得覆盖高优先级原值。

### 4.2 评估字段

`L4两阶段复核_全量368条_合并版_v1.0.csv` 提供：

- 介入类型；
- 是否核心介入点；
- D1–D6；
- 总分；
- 推导 Tier；
- 资金安全强制关卡；
- 物理执行类；
- 复核备注。

这些字段属于“正式复核层”，不覆盖数据库字段。页面同时保留：

```text
database_tier
review_tier
tier_conflict
```

面板 C 的初始卡位使用 `review_tier`；没有复核记录时才退回 `database_tier`；两者都没有时进入“未评估”。

## 5. 各面板统一规则

### 面板 A：流程蓝图

输入优先级：

1. 生效流程蓝图中的显式步骤和连接；
2. 正式流程/SOP中的显式步骤；
3. 只有 L4 清单时，展示结构清单，不画箭头。

约束：

- 只有源文件出现的判断才能画菱形；
- 只有源文件出现的回退、并行和触发才能画对应连接；
- 支链不得擅自并入主链；
- 每个步骤同时显示 L4 编码、活动、交付物、复核 Tier；
- 蓝图缺失时显示“当前只能生成 L4 结构，不能确认流程顺序”。

### 面板 B：人工控制与协作

固定字段：

```text
L4编码
活动
数据库Tier
复核Tier
主责A
执行R
介入类型
是否核心介入点
强制关卡
异常/fallback
证据来源
```

岗位责任没有数据库桥接时，可以展示蓝图责任，但必须标注“材料补充”。

### 面板 C：AI任务工作坊

固定列：

```text
Human / Hybrid / Aug / Auto
```

每张卡固定展示：

- L4 编码；
- 交付物；
- 复核 Tier / 数据库 Tier；
- 介入类型；
- D1–D6；
- 强制人工关卡；
- 来源标识。

拖动规则：

- 初始位置来自正式复核；
- 调整后加橙框并标记“工作坊共识”；
- 浏览器 `localStorage` 按 `L3编码 + 模板版本` 保存；
- 重置恢复正式复核建议，不恢复旧的工作坊结果；
- 不把 L4 人为拆成更细任务，除非存在可追溯任务来源。

### 面板 D：AI机会优先级

四象限结构固定：

1. 高价值·易实施；
2. 高价值·需治理；
3. 待补价值评估；
4. 暂缓。

规则：

- D1–D6 和总分只解释可行性，不等于业务价值；
- 没有逐 L4 价值数据时，所有卡初始进入“待补价值评估”；
- 不得根据 Tier、文字印象或总体价值编造不同二维坐标；
- 每行展示流程背景、数据依据、风险限制和当前位置解释；
- 拖动后的象限位置统一标记“工作坊共识假设”。

### 面板 E：L4交付物地图

固定叙事：

```text
L2能力 → L3目标 → L4交付物 → 具体能力/AI介入方式 → 价值节点
```

规则：

- L4交付物是主节点；
- L2只展示真实桥接，不用大能力名称代替具体能力；
- “具体能力”必须来自规则、Skill设计或可追溯任务材料；
- 没有具体能力时显示“待拆解”，不能沿用整个L2；
- 价值节点只使用数据库桥接；蓝图陈述可作为补充层并明确未入库；
- 交付物上显示复核 Tier、D1–D6总分和人工关卡。

### 面板 F：SSOT与证据

必须包含：

- 数据库原值；
- 正式复核值；
- 蓝图/OB补充值；
- 冲突状态；
- 缺失字段；
- 来源路径或表名；
- 来源主键；
- 版本/日期；
- 本页生成时间。

面板 F 是其他所有面板的追溯底座，不得只列“数据来源”而不列具体对象。

### 负责人决策

固定输出不超过四项：

1. 本 L3 是否值得继续；
2. 建议先验证哪些 L4/交付物；
3. 哪些人工或合规关卡不可绕过；
4. 进入下一阶段前还缺什么。

语言面向业务负责人，不输出数据库表名、算法语言或无关全局统计；技术证据放在面板 F。

## 6. 缺数降级规则

| 缺失情况 | 页面处理 |
|---|---|
| 无蓝图 | A保留为L4结构视图，不画流程连接 |
| 无L2桥接 | E显示“L2桥接待补”，不编造能力 |
| 无VN桥接 | E显示0条数据库映射；蓝图映射单列 |
| 无D1–D6 | C可按数据库Tier起始；D全部待补评估 |
| 有D1–D6、无逐L4价值 | D展示可行性依据，但全部待补价值评估 |
| 无岗位桥接 | B显示材料责任或空白，并标注来源级别 |
| 数据库与复核Tier冲突 | 两值并列，产生CONFLICT，不自动裁定 |
| OB知识待复核/源失效 | 不进入业务面板，只进入F审计记录 |

## 7. 统一页首指标

页首只允许以下指标，顺序固定：

1. L4数量；
2. 蓝图主链步骤数；
3. 正式复核 Tier 分布；
4. D1–D6完整度；
5. VN–L4数据库桥接数；
6. Gate M/E/A；
7. 当前阻断项数量。

数据库 Tier 分布不与复核 Tier 混为一个数字；需要时在指标详情中并列。

## 8. 浏览器交互与保存

V1 独立 HTML 仅允许保存：

- 面板 C 卡片调整；
- 面板 D 象限调整；
- 负责人备注；
- 工作坊时间。

保存键格式：

```text
vnw:l3-model:v1:{l3_code}:{panel}
```

本地保存内容必须标记 `CONSENSUS`，不得改变页面加载的事实与复核数据。

## 9. 三个回归样本

统一模板必须通过：

| 样本 | 主要验证点 |
|---|---|
| L3-IRI | 有蓝图、流程连接、角色补充和交付物地图 |
| L3-IBRD | 多判断点、合规决策、工作坊拖动 |
| L3-COM | 18条L4、368条复核数据、Tier冲突、资金安全关卡 |

验收标准：

- 三页面板顺序完全一致；
- 同一字段使用相同名称和颜色；
- 相同缺失状态使用相同文案；
- C/D交互行为一致并可本地保存；
- F可追溯到具体表、文件和记录；
- 不因某个样本材料更丰富而改变模板骨架。
