# L3 流程模型统一模板 v1.0

> 日期：2026-07-29  
> 状态：冻结为 IRI、IBRD、COM 三个 Demo 的统一重构基线  
> 适用范围：统一 React 流程模型组件；独立 HTML Demo 仅作为历史样式基线  
> 核心原则：结构固定、内容自适应；缺失即声明缺失，不编造补齐。
> 2026-07-30补充：正式纳入L4 Skill封装可行性独立分析轴、面板级说明和输入谱系。

## 1. 模板目标

同一套模板必须同时回答六个问题：

1. 这个 L3 实际如何流转；
2. 哪些环节必须由人负责或复核；
3. 每个 L4 交付物适合怎样的人机分工；
4. 哪些 L4 值得优先讨论，依据是否充分；
5. AI 重塑了哪些交付物的生产逻辑；
6. 负责人本轮需要作出什么决定。

不同 L3 只允许改变业务内容、数据数量和缺失状态，不允许改变面板语义、证据语言和交互规则。

## 2. 固定页面结构

页面顺序固定如下，任何样本不得重排：

| 顺序 | 模块 | 固定用途 | 是否允许隐藏 |
|---|---|---|---|
| 0 | 页首摘要 | L3定义、Gate、完整度、证据快照 | 否 |
| A | 流程蓝图 | 展示真实步骤、顺序、箭头、决策点、回退线 | 否 |
| E | L4交付物地图 | 承接流程，展示L3目标—L4交付物—具体能力—价值节点 | 否 |
| C | AI任务工作坊 | 把L4下钻为可追溯任务，按 Human/Hybrid/Aug/Auto 拖动 | 否 |
| B | 人机协作与控制 | 展示AI责任边界、人工触发条件、控制门和异常承接部门 | 否 |
| D | AI机会优先级 | 四象限工作坊，区分数据判断与共识假设 | 否 |
| 结论 | 负责人决策 | 将前述分析收敛为当前L3的任务级决策项 | 否 |
| F | SSOT与证据 | 原始字段、来源、冲突、缺失和版本 | 否，可折叠 |

“不允许隐藏”不代表必须生成内容。缺少输入时保留面板并显示统一缺失态。

固定叙事链为：`流程怎么运行 → 交付什么 → 任务如何拆分 → 人机如何协作 →
先做什么 → 负责人拍板 → 查看证据`。面板字母表示稳定模块身份，不表示页面排序。

## 3. 四层证据视觉

所有展示内容必须属于以下一层：

| 层 | 含义 | 默认视觉 | 使用规则 |
|---|---|---|---|
| 数据库事实 | PostgreSQL 当前原值 | 蓝色 | 不被其他来源静默覆盖 |
| 正式复核 | 368条两阶段复核表等已形成的逐L4评估 | 绿色 | 可作为工作坊初始建议，必须并列保留数据库原值 |
| 材料补充 | 生效蓝图、正式SOP、OB定稿知识 | 黄色或紫色 | 显示文件、版本、状态、置信度 |
| 工作坊共识 | 拖动、调整、负责人确认 | 橙色 | 只保存在浏览器，不冒充SSOT |

缺失、冲突、待复核分别使用：

- `MISSING`：灰色；
- `CONFLICT`：红色；
- `UNVERIFIED`：虚线黄色；
- `CONSENSUS`：橙框。

## 4. 固定数据优先级

### 4.1 事实字段

编码、名称、数据库交付物、数据库 Tier、桥接关系等事实字段遵循：

```text
PostgreSQL权威库 > 正式源文件 > 生效蓝图/SOP > OB定稿知识
```

低优先级来源不得覆盖高优先级原值。

### 4.2 评估字段

`L4两阶段复核_全量368条_合并版_v1.0.csv` 提供：

- 介入类型；
- 是否核心介入点；
- D1–D6；
- 总分；
- 推导 Tier；
- 资金安全强制关卡；
- 物理执行类；
- 复核备注。

这些字段属于“正式复核层”，不覆盖数据库字段。页面同时保留：

```text
database_tier
review_tier
tier_conflict
```

面板 C 的初始卡位使用 `review_tier`；没有复核记录时才退回 `database_tier`；两者都没有时进入“未评估”。

### 4.3 Skill封装可行性字段

`L4流程_Skill封装可行性评估_确认最终版_v2.xlsx`提供：

- 动作性质；
- 动作单一性；
- A/B/C/F封装档位；
- 判断依据；
- 资金安全强制关卡；
- 物理执行类。

这组字段回答“该动作适合怎样封装”，与D1–D6/Tier回答的“实际需要多少人工判断”
相互独立，禁止用A/B/C/F覆盖Auto/Aug/Hybrid/Human。

双轴设计路径固定为：

```text
A + Auto/Aug → 优先进入Skill原型候选池
A + Hybrid   → Skill执行，人工判断或批准
B            → 先补模板、规则固化或系统接口
C            → 优先Agent辅助或决策支持，不直接封装确定性Skill
F            → 不封装物理动作，只优化前后信息流
```

双轴规则只生成“设计路径”，不生成面板D的正式象限坐标。SFC/SPE六条基于口头确认的
例外重分类必须进入`CONSENSUS + UNVERIFIED`层，标记“待书面佐证”，不得参与正式
Skill优先级自动判断。

## 5. 各面板统一规则

### 面板 A：流程蓝图

输入优先级：

1. 生效流程蓝图中的显式步骤和连接；
2. 正式流程/SOP中的显式步骤；
3. 只有 L4 清单时，展示结构清单，不画箭头。

约束：

- 只有源文件出现的判断才能画菱形；
- 只有源文件出现的回退、并行和触发才能画对应连接；
- 支链不得擅自并入主链；
- 每个步骤同时显示 L4 编码、活动、交付物、复核 Tier；
- 蓝图缺失时显示“当前只能生成 L4 结构，不能确认流程顺序”。

### 面板 B：人机协作与控制地图

本面板不是RACI矩阵，也不是岗位替代热力图。固定回答：

```text
L4活动
AI负责什么
人负责什么
什么情况触发人工介入
哪个控制门不能自动越过
异常最终转给哪个岗位族/部门
```

协作逻辑固定为：

```text
AI执行标准任务 → 质量检查
                  ├─ 正常：进入下一步
                  └─ 异常：转人工判断
                           └─ 资金/合规事项：通过强制控制门后继续
```

规则：

- 页面默认不显示具体人名，避免把当前个人分工固化为岗位设计；
- 岗位族优先使用正式岗位族材料；
- 部门或角色责任没有数据库桥接时，可使用蓝图RACI，但必须标注“材料补充”；
- “AI负责”必须来自面板C有来源的任务、交付物生产逻辑或正式控制规则；
- “人负责”重点描述判断、审批、例外处理和最终责任，不能只重复部门名称；
- “触发人工”必须给出可观察条件，例如低置信、金额不平、规则冲突或阈值失败；
- 正式复核的介入类型、核心介入点、资金安全关卡优先进入控制门；
- 标准RACI如需展示，只作为折叠补充证据，不作为面板B主体；
- 面板B定义责任边界，面板C用于讨论具体任务的Human/Hybrid/Aug/Auto归类。

### 面板 C：AI任务工作坊

固定列：

```text
Human / Hybrid / Aug / Auto
```

每张卡固定展示：

- 任务ID与任务名称；
- L4 编码；
- 交付物；
- 任务级AI分工草稿；
- 任务说明或质量要求；
- 来源标识。

任务来源优先级：

1. 蓝图明确 `sub-step`；
2. SOP或正式流程中的步骤；
3. 规则空白地图的A/B/C/D标签、Gap或控制步骤；
4. 正式复核/OB定稿控制要求；
5. 仅有L4名称和输入输出时，只生成一张“L4级任务”，标记“待进一步拆分”。

每个L4至少有一张任务卡，但不得为了数量凭空拆任务。任务初始AI分工属于
`DERIVED` 分析草稿，必须记录推导依据，不等同于L4复核Tier。

拖动规则：

- 初始位置来自任务级分析草稿；L4复核Tier只作为上层约束；
- 调整后加橙框并标记“工作坊共识”；
- 浏览器 `localStorage` 按 `L3编码 + 模板版本` 保存；
- 重置恢复任务级分析草稿，不恢复旧的工作坊结果；
- 不把 L4 人为拆成更细任务，除非存在可追溯任务来源。

### 面板 D：AI机会优先级

四象限语义固定：

1. 优先验证；
2. 治理后推进；
3. 补数据/规则后推进；
4. 暂缓自动化。

规则：

- D1–D6 和总分只解释可行性，不等于业务价值；
- 每个L4固定展示：数据依据、流程背景、风险/限制、当前建议；
- 系统可以综合D1–D6、交付物角色、熔断/强制关卡和规则空白形成
  “分析草稿归类”，但必须明确标记为 `DERIVED`，不得使用数据库事实视觉；
- 缺少逐L4量化业务价值时，不显示伪造的精确X/Y坐标；
- 分析草稿必须解释为何进入当前位置，不得只显示数量或Tier；
- 拖动后的象限位置统一标记“工作坊共识假设”。
- A/B/C/F只作为封装路径和风险背景；没有逐L4四维分析时仍不得据此自动摆放象限。

### 面板 E：L4交付物地图

固定叙事：

```text
L2能力 → L3目标 → L4交付物 → 具体能力/AI介入方式 → 价值节点
```

规则：

- L4交付物是主节点；
- 每个L4模块固定包含：交付物角色、所需具体能力、AI重塑方式、质量锚点；
- 交付物角色至少区分“价值交付物、支撑交付物、控制交付物”；
- 角色分类必须依据VN组成、流程位置和控制性质，并进入证据审计；
- L2只展示真实桥接，不用大能力名称代替具体能力；
- “具体能力”必须来自规则、Skill设计或可追溯任务材料；
- 没有具体能力时显示“待拆解”，不能沿用整个L2；
- 价值节点只使用数据库桥接；蓝图陈述可作为补充层并明确未入库；
- AI重塑方式必须说明“生成、识别、校验、拦截、评估或人工裁定”的边界；
- 质量锚点优先使用输出验收、规则、KPI、强制关卡和可追溯要求；
- 交付物上同时显示复核 Tier、D1–D6总分和人工关卡。
- 每个L4同时显示Skill封装档位、动作性质、动作单一性、判断依据与双轴设计路径；
- 复合动作只触发“继续拆任务”提示，不能用L4名称自动生成虚假任务；
- 待佐证封装结论使用共识层视觉，不与正式复核使用相同视觉语言。

### 面板 F：SSOT与证据

必须包含：

- 数据库原值；
- 正式复核值；
- 蓝图/OB补充值；
- 冲突状态；
- 缺失字段；
- 来源路径或表名；
- 来源主键；
- 版本/日期；
- 本页生成时间。
- 本 Demo 实际采用的数据库表、文件和方法论；
- 每一类输入对当前 L3 分析带来的具体作用；
- 数据库记录键、CSV/XLSX 行号和 Markdown 行号；
- 模型名称、提示词版本、输入快照 Hash 和分析状态。

面板 F 是其他所有面板的追溯底座，不得只列“数据来源”而不列具体对象，也不得
把整个知识库清单冒充为“本 Demo 已使用的证据”。只展示本次事实包和模型分析真正
使用的来源，并说明“哪一类思考带来了什么输入”。

### 面板级说明

- 页首 Gate 区必须解释 Gate M（能否建模）、Gate E（证据充分度）和 Gate A
  （能否进入 AIT），并逐项列出当前 L3 的判断依据；
- 每个面板右上角显示该面板的 SSOT、补充来源和模型分析逻辑；
- 面板 D 必须解释“优先验证、治理后推进、补数据/规则后推进、暂缓自动化”四种
  归类的业务含义；
- 面板 E 必须提供 Auto/Aug/Hybrid/Human 的中文解释，标签颜色保持一致；
- 右上角说明不能替代面板 F 的逐来源、逐位置追溯。

### 负责人决策

负责人决策必须回到日常工作和任务，不重复面板中的数据健康结论。第一部分固定为
“建议先试的AI任务”，按优先级列出3–5项，每项包含：

1. 任务ID、父L4和任务名称；
2. 为什么适合先试；
3. 首轮最小范围；
4. 必须保留的人工边界；
5. 负责人需要拍板的具体事项。

优先推荐原则：

- 日常重复频率或人工耗时有真实证据；
- 输入输出可观察，可与人工结果并行比对；
- 可以影子模式或只读方式验证；
- 失败可以退回人工；
- 不直接自动放行资金、合规结论或不可逆发布。

第二部分固定提示负责人同时决定：

1. 试点Owner、参与部门、投入边界和停止条件；
2. 验收指标、人工现状基线和通过门槛；
3. 不可绕过的人工/资金/合规质量门；
4. 可用数据、脱敏范围、规则版本和验收样本。

不得虚构节省比例、ROI或准确率。没有基线时，应要求试点前先测量基线，而不是给出估算值。
语言面向业务负责人，不输出数据库表名、算法语言或无关全局统计；技术证据放在面板 F。

## 6. 缺数降级规则

| 缺失情况 | 页面处理 |
|---|---|
| 无蓝图 | A保留为L4结构视图，不画流程连接 |
| 无L2桥接 | E显示“L2桥接待补”，不编造能力 |
| 无VN桥接 | E显示0条数据库映射；蓝图映射单列 |
| 无D1–D6 | C只能使用有来源的任务性质草稿；D以待补数据为主，不生成精确坐标 |
| 有D1–D6、无逐L4价值 | D可形成明确标记的分析草稿归类，但不得生成或声称正式X/Y坐标 |
| 无岗位桥接 | B显示材料责任或空白，并标注来源级别 |
| 数据库与复核Tier冲突 | 两值并列，产生CONFLICT，不自动裁定 |
| OB知识待复核/源失效 | 不进入业务面板，只进入F审计记录 |
| Skill封装评估待书面佐证 | E显示待佐证标签；D不进入正式优先级自动判断 |
| 缺少Skill封装评估 | 不阻断Gate M；E显示封装待评估 |

## 7. 统一页首指标

页首只允许以下指标，顺序固定：

1. L4数量；
2. 蓝图主链步骤数；
3. 正式复核 Tier 分布；
4. D1–D6完整度；
5. VN–L4数据库桥接数；
6. Gate M/E/A；
7. 当前阻断项数量。

数据库 Tier 分布不与复核 Tier 混为一个数字；需要时在指标详情中并列。

## 8. 浏览器交互与保存

V1 独立 HTML 仅允许保存：

- 面板 C 卡片调整；
- 面板 D 象限调整；
- 负责人备注；
- 工作坊时间。

保存键格式：

```text
vnw:l3-model:v1:{l3_code}:{panel}
```

本地保存内容必须标记 `CONSENSUS`，不得改变页面加载的事实与复核数据。

## 9. 三个回归样本

统一模板必须通过：

| 样本 | 主要验证点 |
|---|---|
| L3-IRI | 有蓝图、流程连接、角色补充和交付物地图 |
| L3-IBRD | 多判断点、合规决策、工作坊拖动 |
| L3-COM | 18条L4、368条复核数据、Tier冲突、资金安全关卡 |

验收标准：

- 三页面板顺序完全一致；
- 同一字段使用相同名称和颜色；
- 相同缺失状态使用相同文案；
- C/D交互行为一致并可本地保存；
- F可追溯到具体表、文件和记录；
- 不因某个样本材料更丰富而改变模板骨架。
