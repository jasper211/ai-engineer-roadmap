# 未用流程数据接入分析模型规划（第一阶段：仅流程数据，不含业务数据）

> 范围说明：本次只解决process_analytics里"已抓取但未展示"和"从未查询"的流程
> 数据，不涉及public/comm_sandbox/fin_sandbox三个业务数据schema——按Jasper
> 的顺序要求，业务数据接入放在下一阶段单独规划。

## 一、现状：分析模型只回答了"能不能AI化"，没回答"该不该投入"和"人还是token"

现有`analysis.tasks[].suggested_tier`+`tier_rationale`本质只回答一个问题：
这条任务技术上能不能自动化。VNW的目标决策——"哪些任务AI化、部门投入人还是
投入token"——还需要另外两层判断，现在完全没有数据支撑：

1. **该不该投入**（价值权重）——这个L3/L4对公司有多重要，优先级该排多前
2. **人还是token**（投入形态）——判定要投入之后，招人补更合适还是做AI更合适，
   取决于人力现状约束

## 二、5个未用数据源，逐一核实覆盖率和可用状态后的结论

### 2.1 KPI贡献度（`dim_kpi`+`bridge_kpi_l3`）→ 补"该不该投入"，但**目前只能当草稿信号，不能当权威权重**

- 覆盖：24条权重记录，覆盖19/74个L3（26%）
- **核实结果：`weight_confirmed`字段24条里4条`blocked`、20条`pending`，零条已确认**——这批贡献度权重目前是彻头彻尾的草稿状态
- 关键字段：`contribution_weight`(权重)、`dim_kpi.is_mark_kpi`(是否Mark关注的核心指标)
- 结论：可以接入分析模型，但必须显式标注"未确认草稿"，不能当成跟D1-D6一样权威的判断依据；且只覆盖26%的L3，多数L3这一项会是空

### 2.2 价值流/客户旅程位置（`dim_vs`+`bridge_l3_vs_stage`）→ 补"该不该投入"（战略视角），覆盖较好

- 覆盖：50/74个L3（68%），比KPI覆盖率高很多
- 关键字段：`stage_sequence`(旅程第几阶段)、`vs_stakeholder`(服务谁)
- 已有真实结论支撑：上次3.1的根因分析发现"旅程越靠前阻断影响越大"、"KA上架/理财师发展两条旅程全线阻断"，都是基于这批数据算出来的，不是新猜测
- 结论：五个数据源里**成熟度最高、最该优先接入**的一个

### 2.3 候选Agent现状（`dim_agent`）→ 原计划补"人还是token"，**现在这条路走不通**

- `owner_position_family`（候选Agent归属岗位族）361条**全部为空**，没法桥接`dim_org`
- 结论：这个数据源目前**只能看`agent_status`（是否已有候选设计构想）本身**，不能用来判断"人力现状"，原规划里"投入形态"这一层要少一个输入来源

### 2.4 岗位/人力现状（`dim_org`）→ 补"人还是token"，可用但要绕开2.3的桥接缺口

- 8个岗位族的`headcount_target_min/max`(编制目标)、`ep_count`(现有人数)、`mark_retained`(Mark保留岗位)都是真实字段
- 但因为2.3的桥接是空的，**目前没有"这条L4属于哪个岗位族"的机械路径**——只能靠L3蓝图里零散的"主责岗位"文字（而且大部分是"待确认NULL"，参考之前查过的ACTV/STLM等蓝图）
- 结论：数据本身可用，但"L4→岗位族"这条关联链目前缺失，是接入前必须先解决的一个真空白

### 2.5 战略分类（`dim_l1`/`dim_l2`/`dim_m_strategy`）→ 补"该不该投入"（战略对齐），覆盖太窄

- 仅5/19/9条，是五个数据源里体量最小的
- 结论：可以接，但权重应该给到最低，覆盖面撑不起一个独立判断维度

## 三、这一阶段建议实际能做的，跟原规划相比收窄了

| 数据源 | 原计划 | 核实后结论 |
|---|---|---|
| KPI贡献度 | 接入价值权重 | 接入，但标"未确认草稿"，26%覆盖 |
| 价值流位置 | 接入价值权重 | **接入，68%覆盖，是这批里最扎实的** |
| 候选Agent | 桥接岗位族判断人力约束 | **桥接字段是空的，这条路线取消** |
| 岗位人力 | 判断人还是token | 数据可用，但缺"L4→岗位族"关联，需要先补这条链路（大概率要靠人工，蓝图里"主责岗位"大部分是NULL） |
| 战略分类 | 补充战略对齐 | 接入，权重最低，覆盖窄 |

**实际可以扎实推进的只有价值流位置（2.2）**；KPI和战略分类（2.1/2.5）能接但必须标草稿/低权重；岗位人力（2.4）这条线因为2.3桥接缺失，要么先做人工关联L4↔岗位族，要么先不接这块。

## 四、前端落点（草案）

- 价值流位置 → 机会台全貌层（L3Models.tsx）新增一个"按价值流"分组/筛选视图，同时在L3详情页面板D标注该L3所属旅程和阶段
- KPI贡献度 → 面板D业务价值参考，明确标注"草稿·未确认"，不跟D1-D6一样当权威事实展示
- 战略分类 → 低优先级，可以先只在面板F证据列表里带出来，不单独做可视化
- 岗位人力 → 待"L4→岗位族"关联问题解决后再定落点，现在没有机械路径，先不做
