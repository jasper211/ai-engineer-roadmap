# VNW · 08 数据血缘图前端展示设计

> **针对 Mark "看下前端展示界面的数据血缘图该如何设计展示"。基于对现有 `DataLineage.tsx` 的源码读解（节点/边/RELATION_TONE/slicing/选中面板/字段血缘均已实装），提出把 04归一族、06角色分类的能力展示出来，并修正"僵尸=未挂L4"的误标。只出设计，不改前端。**

## 一、现状（现有实现已具备的能力）
- 力导向图（force layout），节点10px半径，三类边分色 + 箭头：view依赖=靛蓝、FK=天蓝、流水线同批=灰虚线（默认折叠）。
- 节点四态 `RELATION_TONE`：绿=已确认关联L4、橙=血缘候选L4、红=疑似僵尸、灰=暂无信号。
- 支持：按 schema 过滤、按 L3 切片、搜表名高亮、选中看上下游+字段级血缘、同名字段跨表索引、僵尸清单+无可查血缘清单汇总。
- 声明原则："边只来自三类真实证据，不做同名字段推测连接"——与本模块方向一致，值得保留。

## 二、要解决的两个核心问题

### 问题1：颜色把"僵尸"语义搞混了，会误导用户
- 现状红色`zombie`仅由 `zombie_flag==='suspected_zombie'` 触发，而那些被标僵尸的表**大多不是僵尸**（历史/版本/配置/字典，见 01-06）。
- 用户看到大红点会误以为"这表废弃了"。**必须脱钩："是否挂L4" ≠ "是否僵尸"。**

### 问题2：41张交付本体的"证据类型"没有可视化表达
- output/rule/workflow/audit 这四类对"AI是否有意义"的判断最关键（rule=逻辑已参数化，是Skill/Auto强信号），但图上看不出。
- 当前节点只有 6~16px 的圆点，没有形状/内徽标区分证据类型。

## 三、展示设计改造方案

### A. 节点语义重组：颜色区分"角色"，徽标区分"证据"，边框区分"版本/僵尸"
建议把"单色点"升级为 **三层视觉**：

1. **填充色 = 角色**（回答"在业务里啥位子"）
   | 角色 | 颜色 | 对应 |
   |------|------|------|
   | 交付本体 | 品牌主色（如紫/蓝实心） | 41张 output/rule/workflow/audit |
   | 服务支撑 | 次级色（如天蓝/teal） | 30张视图/维度/桥接 |
   | 独立/工具/配置 | 中性灰 | 33张字典/空表/系统 |
   | 疑似僵尸（真断点） | 红（保留，但仅限真僵尸） | 经 3证 判定者 |

2. **内嵌图标/角标 = 证据类型**（仅在交付本体节点，用户可选开）
   - output=实心圆点、rule=菱形、workflow=方形、audit=三角；
   - 或更轻的写法：节点上层叠一个小 badge 字母（O/R/W/A）。
   - 对"AI是否有意义"的判断：让用户一眼看到哪些环节逻辑已参数化（rule）→ 强信号。

3. **边框/**线型 = 版本关系（18表7族）
   - 版本族内历史/快照/副本节点：**虚线边框** + 鼠标悬停显示"current/history/snapshot/duplicate"；
   - 跨schema重复（config_quarter×2等）：同 version_group 节点用同色**细连接线虚线**圈联提示"疑似同一逻辑对象"。

### B. 边保持四类证据分级（不混强度）
在现有 id 线 + 灰虚线基础上，**新增第四类"业务语义连接"**，用一个独有的线色/线型（如 深绿实线/或点划线），并明确强度排：view/FK > 语义桥接 > 流水线同批 > 命名/引用推断（仅候选）。图例同步加第4条。

### C. 修正"僵尸"清单与文案
- 把当前"疑似僵尸表"列表改为**分类**呈现（不再一锅红）：
  - 真断点（待人工核实，红）—— 3证判定者
  - 版本/快照（补版本指针，橙/提示）—— 历史/归档/快照
  - 配置/字典（语义未排到，灰）—— 规则/维度/配置
  - 0行未启用（never_activated，白/浅灰）
- 文案同步改为："血缘查不到≠废弃；可能是版本/配置/未开启，逐类核实"。

### D. 新增"角色/证据/版本"三维视图切换（核心）
在顶部加一个 `视图模式` 切换，让用户按需切换关注维度：
- **血缘视角**（默认，现状）
- **角色视角**：按 交付本体/服务支撑/独立 着色分组，看"这表在业务里占哪个生态位"
- **证据视角**：高亮所有 rule/output 规则类表，服务"判断 AI 在哪些环节可接管"
- **版本视角**：只显示7个版本族 + 它们的 current/history/duplicate 关系，看多版本混表

### E. 辅助面板增强（沿用现有选中 float）
- 选中交付本体时：显示已确认L4 + evidence_type + confidence，并列出"同一族内其它版本表"（跳转）；
- 选中版本表时：提示"这是 X 的历史归档版，主表是 Y（跳转）"，防止用户误以为孤立。

### F. 新表进入的 UI 支持（配合持续框架）
- 对 `never_activated`（0行）节点，给浅灰描边 + tooltip"0行未启用"；
- 对"语义未排到"节点，tooltip 标注"已核实仓库内血缘均无，待 bridge batch 覆盖"——与现有"确证生产者在外"文案区分。

## 四、不改的（保留现状优势）
- 力导向布局、schema/L3 过滤、搜表名高亮、字段级血缘面板、同名字段索引——这些已有且正确，保留。
- "边只来自真实证据、不做同名字段推测"的总原则——保留，只新增"语义桥接"这一种经过人工核实的证据类型。

## 五、改造优先级排序（建议）
1. **节点角色着色 + 僵尸清单分类**（改颜色/文案，收益最大、改动最小）——解决误导根子。
2. **证据类型角标**（O/R/W/A badge，低代码量）——服务"AI是否有意义"。
3. **版本族虚线框/连线**（视觉表达 18表7族）——呼应本模块归一化。
4. **三维视图切换**（前端结构改造，较大，放最后）。
