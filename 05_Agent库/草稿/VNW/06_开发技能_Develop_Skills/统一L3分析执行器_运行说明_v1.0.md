# 统一 L3 分析执行器运行说明 v1.1

> 更新日期：2026-07-30

## 1. 固定生产链

```text
源数据同步 → snapshot → gate → prepare → run/import
→ validate → publish → frontend
```

- `snapshot`：冻结单 L3 事实、来源位置和快照 Hash；
- `gate`：执行 Gate M/E/A；
- `prepare`：生成只包含当前 L3 事实的运行包；
- `run/import`：调用 VNW 模型，或导入外部模型 JSON；
- `validate`：检查快照时效、L4 覆盖、证据引用、任务归属和输出契约；
- `publish`：发布 `L3-CODE.model.json`，已有包先备份，不静默覆盖；
- `frontend`：统一 React 页面读取快照与分析包。

## 2. 构建快照

```bash
python3 04_定义Agent_Define_Agent/agents/agent.py \
  --build-all-model-snapshots
```

指定 L3：

```bash
python3 04_定义Agent_Define_Agent/agents/agent.py \
  --build-model-snapshots --l3-code L3-COM --l3-code L3-IRI
```

## 3. 准备并运行完整分析

```bash
python3 04_定义Agent_Define_Agent/agents/agent.py \
  --prepare-l3-analysis L3-COM

python3 04_定义Agent_Define_Agent/agents/agent.py \
  --run-analysis-dir <analysis_runs下的运行包目录>
```

复制 `02_配置项目_Configure_Project/deepseek_config.example.json` 为本地配置并填写
VNW 自己的 Key，或使用 `DEEPSEEK_API_KEY`。禁止读取其他 Agent 的密钥文件。

## 4. 导入外部模型结果

```bash
python3 04_定义Agent_Define_Agent/agents/agent.py \
  --run-analysis-dir <运行包目录> \
  --import-analysis-output <模型输出JSON>
```

导入不会绕过快照、证据和输出契约校验。

## 5. 修复已有分析包

当已有包的任务或负责人决策不满足统一契约时：

```bash
python3 04_定义Agent_Define_Agent/agents/agent.py \
  --prepare-analysis-repair L3-IRI
```

修复必须保留其余有效分析，不得借修复改写未在目标范围内的模块。

## 6. 分批刷新 L4

为控制模型上下文和审核范围，单批最多 6 个 L4：

```bash
python3 04_定义Agent_Define_Agent/agents/agent.py \
  --prepare-analysis-l4-refresh L3-COM \
  --analysis-l4-code L4-COM-01 \
  --analysis-l4-code L4-COM-02
```

刷新只允许修改指定 L4 及其关联任务、优先级和决策引用。未知证据引用进入审计，
不得直接发布。

## 7. 任务和证据要求

- 每个 L4 至少一条有来源的具体任务；
- 蓝图对同一 L4 给出多个独立步骤时分别形成任务；
- Skill 评估标记“复合动作”时原则上至少两条任务；
- 数据库键、表格行号和 Markdown 行号随事实包保留；
- 模型只能引用当前快照中的 ACTIVE 证据；
- 待佐证、工作坊共识和临时评估不进入模型分析；
- Skill A/B/C/F 与 Human/Aug/Hybrid/Auto 不得混为一个判断轴。

## 8. 安全边界

- 模型只能读取运行包中的事实；
- 输入快照变化后旧结果禁止发布；
- 所有输出标记 `MODEL_DRAFT`；
- 发布不等于负责人确认；
- 不修改数据库或知识库；
- 浏览器工作坊结果不进入分析包。
