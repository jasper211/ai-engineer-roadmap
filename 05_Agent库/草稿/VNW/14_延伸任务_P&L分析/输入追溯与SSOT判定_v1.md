## 1. 先厘清：两个「世界」不是同一套分类

入口① 场景分析当前的 `PNL-001` 用**流程域视角**（L3 流程：L3-COM / L3-HRA / L3-HRM / L3-SSVA / L3-CPM…），把 P&L 拆成 **收入 / 佣金成本 / 采购成本 / 运营费用 / 人力费用** 五线，并按 `state A/B/C` + `confidence L1-L3` 打标。

P&L 专案当前用的是一套**管理维度视角**：**财务定义的 4 类 × 12 个市场细分**（<Leader/PMO/公司/经营板块/收入类型/成本类型>），外加 **7 线 Baseline 映射**，并强调「MGA TA 与 TTL Direct Issue 分开建模、最后合并」。

→ 结论：**两个分类体系根本不同，且当前没有桥接关系。** 这正是入口① 场景分析里反复出现「KPI_04 引用 6 个 L3 有 3 个不在库」「待财务负责人确认口径」的深层原因——VNW 入口① 拿的不是 P&L 专案的权威分类。

## 4. 核心结论：**当前输入足以支撑"输入结构"优化，但不足以下结论优化**

**✓ 能支撑的（且证据充分）：**
1. **入口① 的分类口径可以被权威化**——从 VNW"流程域 5 线猜测"切到 P&L"财务 4类×12市场细分×公司"。权威链条：**启动会 D2 → 財務維度梳理 → Baseline说明**，三者成链。
2. **数据就绪/缺口清单可以吃真实表**——`TTL xlsx` 提供真实行数、7线段、订单/伙伴/产品钻取；`06_异常补证` 直接对位入口① C 状态组件。
3. **"最难算根因（多主体×多业务线）"从"推断"升级为"已成文"**——启动会 D7 + 財務維度梳理 双重坐实。
4. **成本/费用"为什么缺"有了权威口供**——困境一（D3）：报销/付款流程不绑定市场细分维度。这是入口① 成本 status=C 的第一现场原因，可写进前端"缺口说明"，而不是猜测。

**⚠️ 尚不能支撑的（optimization 前提未满足部分）：**
- **SSOT 尚未冻结**：P&L 项目反复强调「先冻结 Baseline、口径与数据契约（Gate），再开发」；当前口径冻结（M3）未到。**口径冻结前，任何"入口① 输入结构优化"都只是建议，不是可上线的 CONFIRMED 结构**。
- **存在多版本未决**：章程/执行计划各有 v1.0 与 v1.1；`業務維度梳理.xlsx` 有 Sheet1/Sheet2/Sheet1(2) 三套结构——**同一份文件内有三套字段**，待收敛。
- **对接尚无桥**：VNW 的 L3 流程模型 ↔ P&L 的财务维度，二者无映射层。无桥则前端仍是两套孤岛。

## 6. 对入口① 内容结构优化的落地建议（仅供派生区采用）

1. **为 PNL-001 的权威维度增加一维 `market_class(4類)/market_segment(12細分)/company`**，字段取 `業務維度梳理.xlsx`，标注来源路径；口径起点注启动会 D2。

3. **「多主体×多业务线」根因落上证据**：标注权威来源=启动会 D7（拆单/分账/回放）+ `業務維度梳理.xlsx`，而非仅 VNW T5 推断。
4. **成本/费用 C 状态的"为什么"补权威口供**：引用启动会 D3「报销/付款流程不绑市场细分维度」，把"为什么缺"写清楚。
5. **口径结论一律加"对标 SSOT 待冻结"标签**：4类/12细分、KPI_04、成本分摊相关，标注「对标 P&L Baseline（待口径冻结）+ 启动会 D*/`業務維度梳理`/TTL」。
6. **保留 7线 ↔ 12细分桥接字段**：入口① 前端若增结构，须像 P&L 专案一样保留「现有 7 线 Baseline 映射」以维持历史可比。
7. **启动会转写按"决策线索"引用而非"任命依据"**：涉及 Owner/任职一律以 W0 正式名单为准（D12 后章程声明），转写仅作口径与痛点证据。
