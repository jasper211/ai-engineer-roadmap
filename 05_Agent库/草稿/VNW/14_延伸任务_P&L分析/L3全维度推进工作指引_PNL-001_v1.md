> **用途**：给流程 Owner 及推进小组一份「照着能干活」的逐模块 L3 推进清单。每个 L3 回答四个问题——**涉及哪些 P&L 范围、现状到哪、缺口该补什么（补蓝图细节 / 新建 L3 / 优化 L4 / 确认 L4 交付物）、谁在何时做什么、验收以什么为准**。
> **信息底座**：VNW `model_snapshots`（status / gate / 价值节点映射 / 交付物覆盖）、`business_scenario_analysis/PNL-001.json`（process_status / process_optimization / data_governance / task_list）、P&L 专案`業務維度梳理`（4类×12细分 / Leader / 公司 / 成本类型）。
> **性质**：VNW 延伸任务派生产物，只读引用，不写回 P&L 专案、不改 VNW 权威源。财务口径待冻结；Gate 结论以快照为准、过门需人工确证；「业务主体↔L3」映射为基于业务划分的分析判断（非 VNW 权威一对一表），供分工参考，落库前须与 PMO/L3 负责人对平。

## 0. 一句话总纲（先看这个）

P&L 涉及的 L3 分四类，**动作类型各不同，别混为一谈**：

| 类型 | 涉及 L3 | 判定动作 | 一句话 |
|---|---|---|---|
| A. 交付物已齐、卡门禁 | L3-COM / L3-HRA / L3-HRM | **优化 L4/价值节点映射**，消除 Gate A「A-004 熔断/无价值节点」 | 你缺的不是交付物，是价值节点链断了 |
| B. 现库有、但价值节点映射缺失 | L3-SSVA（服务结算与价值核算） | **补蓝图细节**（价值节点-L4 映射=0，先建映射） | 交付物在、节点没接上，蓝图层断 |
| C. 现库无、需要新建 | 采购 L3 / 月结审核 L3 / 跨部门对账 L3 | **新建 L3**（含 L4 节点定义） | P&L 三块核算无流程，只能从零建 |
| D. 部分支撑 / 待评估 | L3-MED / L3-CPM / L3-BSRV | 属部分支撑，**确认交付物与关联必要性**后定是否留用 | 别一上来推它，是先确认它该不该在链上 |
| E. 委外 / 失效引用 | L3-STLM（委外）；L3-CBD/CMU/CVI（不在库） | **升级专案协调**（委外）/ **移除修正 KPI_04 引用** | 不归流程 Owner 推，但要在 KPI_04 里清理 |

> **核心指令**：交付物覆盖（deliverable covered/total）已满 ≠ 流程可过门。**Gate A 才是门**，看 A-001~A-004 逐条，缺哪条补哪条。

## 3. 逐 L3 执行卡（照着做）

### 3.1 L3-COM 佣金全链路管理 —— 本期最高优先级

- **涉及范围**：佣金收入线 + 佣金拨出成本线（全业务主体的主支撑）。
- **现状**：FULL_MODEL；Gate A 里 **A-001/A-002/A-003 全 ✅，仅 A-004「熔断或无价值节点」❌**；交付物 18/18。
- **判定**：**优化 L4/价值节点映射**（不是补交付物、不是新建）。
- **具体动作**：
  1. 拉取 L3-COM 的价值节点链，定位**熔断点或无价值节点**（触发 A-004 的具体节点）；
  2. 对熔断节点：接通其到下游 L4 的价值映射；对无价值节点：标注或移除或补价值声明；
  3. 与财务确认佣金**应收/实收口径**（PMR/PL 定义已在启动会 D1 确认主体化，佣金口径 D1 待财务拍板）。
- **验收**：`gates.A.checks` 中 A-004 → ✅，Gate A 从 BLOCKED → PASS。
- **数据证据**：fact_commission_rate 25,111、agg_sales_base 6,399、agg_source_commission_wide 5,734、agg_market_commission_tier_rate 7,518（A 级就绪）。
- **依赖**：财务口径（W1 前）；**无源流程权外**。
- **归属**：流程 Owner 牵头 + L3-COM Owner + 财务。

### 3.2 L3-HRA 人力分析与决策支持流程

- **涉及范围**：人力费用线。
- **现状**：FULL_MODEL；Gate A 同样**仅 A-004 ❌**；交付物 7/7 满（含 L4-03「人员成本分析」）。
- **判定**：**优化 L4/价值节点映射**（重点在 L4-03 人员成本分析的价值节点链）。
- **具体动作**：
  1. 检视 L4-03「人员成本分析」的价值节点映射，消除熔断/补无价值节点；
  2. 把「各类分析报告」交付物结构化为**可校验的人力成本字段**（对应 data_governance 需建的 `fact_employee_compensation`，T2）。
- **验收**：Gate A → PASS；人力成本交付物可产出结构化字段。
- **依赖**：HR 系统的薪酬数据导入（T2，P0）。
- **归属**：流程 Owner + L3-HRA Owner + HR/数据。

### 3.3 L3-HRM 人员全生命周期管理流程
